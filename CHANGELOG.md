# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed

- Linux release binary of `sqler` under the 60 MB budget: `[profile.release]` now has `strip = "symbols"` (the ELF symbol table was about 23 MB of 78 MB; macOS and Windows keep symbols in side files) and `codegen-units = 1` (about 9 MB less, release build about 1.7x slower). Release backtraces show addresses, not function names (AGENTS.md section 10). `size.yml` also prints the largest sections (`size -A`) on Linux, and the largest crates (`cargo bloat --crates`, from a separate unstripped build) on push to `main` and manual runs only, not on pull requests; report only. Measurements in `docs/src/benchmarks.md`.
- Result grids are bounded (ADR-0027): a result loads one page at a time (`result_page_rows` in `settings.toml`, default 100,000, range 1,000 to 10,000,000, or 64 MiB of cells) and then pauses with `N rows loaded; more rows available`. The new **Fetch more** button and `grid:fetch-more` command load the next page; Cancel or closing the tab ends a paused result. A paused statement holds the tab session, so later statements of a script stay pending until fetch-all or cancel. Rows are stored in a compact per-batch layout (new `GridLimits`, `GridCancel`, `RowRef`, `CellRef`; the read API no longer returns `&Row`); the synthetic grid, the `grid_viewport` bench and `grid_scroll` stay unbounded. Figures in `docs/src/benchmarks.md`.
- `grid_viewport` and `browser_tree` benchmarks gate on the minimum over `--reps` (3) repetitions with an absolute `--slack-ns` (100 ns and 250 us), so noise on shared CI runners no longer fails unrelated pull requests; a 2x slowdown still fails. `bench.yml` and `docs/src/benchmarks.md` updated.

### Fixed

- `sqler-completion` diagnostics: `RETURNING` of an `INSERT ... SELECT` no longer reports `AmbiguousColumn` (it sees the insert target only); `pg_temp`, `pg_temp_N` and `pg_toast_temp_N` are PostgreSQL system schemas; `public.users.id` matches `FROM users`; `DELIMITER` is a client command only at the start of a line; a routine without a custom `DELIMITER` ends at its own `;` so later statements are still checked, and nothing inside a routine definition is reported; `SET` target detection is linear (a 32,000-branch `CASE` update no longer takes seconds). The completion bench reports the minimum over repetitions for `hover_p95_ns` and `diagnose_p95_ns` too.

### Added

- `sqler-export`: writers for `CSV` (RFC 4180; delimiter, header, `NULL` text, line ending, opt-in `neutralize_formulas`), `JSON` (array of objects, `JSON` columns embedded), `SQL` `INSERT` (dialect-quoted identifiers, literals per dialect, rows per statement) and Markdown tables, behind a push-style `RowWriter` API with a `Registry`, an `Exporter` (buffering, cancel, progress) and `export_to_vec`; 1M-row streaming test and `export_throughput` bench (ADR-0028)
- `sqler-sql`: `sql_literal`, `push_literal` and `string_literal` render a value as a SQL literal per dialect; the lexer (`tokenize`, `Token`, `TokenKind`) is public (ADR-0028)
- `sqler --open-sessions` (measurement option, next to `--exit-after-first-frame`): after startup it opens every saved connection through the normal connect pipeline (ADR-0016), logs one `sqler: open-sessions: ...` line per connection on stderr and idles, so the idle RSS with sessions open can be measured. SQLer itself never prompts (an SSH agent may) and prints no secret; skip lines hold the connection name and a fixed reason per failure kind (the error text is never printed, so no database target, credential or key path can leak); only the unknown and changed SSH host key reasons add the jump `host:port`: connections with a keychain secret, or an unknown or changed SSH host key, are skipped with a line. New `Binary size` workflow (`.github/workflows/size.yml`) builds `sqler-app --release --locked` on Linux, macOS and Windows (main, `workflow_dispatch`, PRs touching `crates/**`, `Cargo.toml`, `Cargo.lock`, `vendor/**`) and prints the size in bytes and MiB next to the 60 MB budget; report only, not a gate. `docs/src/benchmarks.md` and `AGENTS.md` §3 describe both methods.
- M3 metrics and the iteration-004 report: fresh cold start, idle RSS, binary size, completion, catalog index and editor benchmark figures in `docs/src/benchmarks.md` (new "SQL editor buffer" section), `docs/reports/iteration-004.md`, roadmap status M3 done.
- Intellisense in the SQL editor: completion while typing and on `editor:trigger-completion` (Ctrl+Space; on macOS the system may use it for input source switching, rebind it or use the palette), hover with column type, nullability and foreign key target, and underlined diagnostics 300 ms after typing, all from the connection's object browser catalog. Missing columns are loaded in the background and a catalog refresh updates suggestions without reopening the tab. New public module `sqler_ui::editor::intellisense` (no GPUI), direct dependency `lsp-types`, `editor_intellisense` benchmark, ADR-0026 and an "Intellisense" section in the SQL editor user guide and the UI architecture page. Limits: snippets are inserted without tab stops; a failed load is retried only after the browser reconnects.
- Query history and saved queries in the desktop app: every statement that finishes, fails or is cancelled in an editor is recorded in `history.jsonl` (SQL before binding, outcome, duration, row count; no error text or parameter values). `history:open` opens a History tab per connection with text search and an "All connections" filter, from which an entry is opened in an editor or run again (through query execution, so the `prod` confirmation still applies); `history:clear` deletes everything after a confirmation. `query:save` saves the editor text as a named query in `queries.toml`; saved queries are listed in a sidebar section and the `query:open-saved` picker, and can be renamed and deleted (with confirmation). All store access runs off the UI thread. New public module `sqler_ui::history` (no GPUI), `Startup.history_dir`, the user guide page "Query history and saved queries" and a section in the UI architecture page.
- Query execution in the desktop app: run the selection, the statement at the cursor or the whole script (`query:run-selection` Cmd/Ctrl+E, `query:run-statement` Cmd/Ctrl+Enter, `query:run-all` Cmd/Ctrl+Shift+Enter, `query:cancel` Cmd/Ctrl+.). Statements come from the `sqler-sql` splitter and stop at the first error; each result streams into its own grid with row count, duration or error, and the run can be cancelled on the server. Placeholders open a parameter dialog and are sent as bound parameters, never spliced into the SQL; cancelling the dialog runs nothing. On a `prod` connection every statement that is not a plain read needs one confirmation that shows its exact SQL, also inside run-all. New public module `sqler_ui::query` (no GPUI), ADR-0024 and the user guide page "Running queries".
- SQL editor tab in the desktop app: a code editor per connection (`gpui-component` editor, tree-sitter SQL highlighting for light and dark themes), header with connection name, colour and environment, multi-cursor editing (Alt-click, add cursor above or below, add next occurrence), bracket matching, `editor:format-sql` for the selection or the whole buffer as one undo step, `editor:new` (Cmd/Ctrl+N), `editor:go-to-matching-bracket`, "Open in SQL Editor" in the object browser and on DDL tabs, and `dev:open-large-sql-script` (10,000 lines). The editor logic is headless in `sqler_ui::editor`; the buffer is handed to query execution through the `RunPort` trait. New `editor_buffer` benchmark. ADR-0025, the user guide page "SQL editor" and an "SQL editor" section in the UI architecture page.
- `sqler-completion`: hover and diagnostics on the same scanner as completion. `hover(&HoverRequest, &dyn SchemaSource)` returns the column type, native type, nullability and foreign key target of the column under the cursor (direct, through an alias, through a bare table name or schema-qualified), the kind and schema of a table, view or materialized view (also through its alias), and the name of a CTE or subquery, `None` for keywords, literals and names it cannot resolve. `diagnose(text, dialect, &dyn SchemaSource)` reports unknown schemas, tables or views, columns and qualifiers as errors and ambiguous columns as warnings, with the byte range of the identifier and a message, per statement; it never flags names of relations whose columns or lists are not loaded, system schemas, tables created in the text, CTE columns it cannot name, or syntax the scanner does not model, or anything inside a stored routine definition (parameters and locals), and follows the dialect's quoting and case rules (`PostgreSQL` exact for quoted names). `SchemaSource` gains `foreign_keys` (default: none) and `MemorySchema` `add_foreign_key`. Property tests (never panics, ranges inside the text, schema-only text has no unknown identifiers), example tests, hover and diagnose scenarios in the `completion` benchmark (p95 well under the 16 ms budget on the 5,000-table schema) and the architecture section "Hover and diagnostics".
- `sqler-completion`: SQL completion engine for `PostgreSQL`, `MySQL`/`MariaDB` and `SQLite`. `complete(&CompletionRequest, &dyn SchemaSource)` is pure and synchronous, works on incomplete SQL (own total lexer, no `sqlparser`), detects the context (relation, select list, `WHERE`, `ON`, `GROUP BY`, `ORDER BY`, `schema.`, `alias.`, `INSERT` columns), resolves aliases, CTEs and subquery aliases with dialect-specific quoting and case rules, offers per-dialect keywords, built-in functions and five snippets, and ranks in-scope columns and prefix matches first. The schema is read through the `SchemaSource` trait over `sqler-core` types (`MemorySchema` for tests); columns that are not loaded produce a `SchemaRequest`, not an error. Proptest and snapshot tests, a 5,000-table `completion` benchmark (p95 budget 16 ms, also run by `bench.yml`), ADR-0023 (including the hover and diagnostics shape) and the architecture page "Completion engine".
- `sqler-catalog` snapshot and name index for intellisense: `Catalog::snapshot()` returns an immutable, `Send + Sync` `CatalogSnapshot` without waiting on the worker (copy-on-write store, sharded maps, unchanged objects shared across refreshes), `lookup` does prefix and fuzzy search over objects and loaded columns, scoped, bounded and ranked, `load_tables` loads the columns of named tables on demand and cancellably, `table_state` tells "not loaded" from "no columns", and `foreign_keys` resolves the targets of loaded tables. ADR-0022, an updated "Schema catalog" page and a `catalog_index` benchmark on 5,000 tables (also run by `bench.yml`).
- `verify-full` TLS through an SSH tunnel on macOS and Linux: `sqler-core` `TlsConfig` gains `server_name`, the connect pipeline sets it to the connection's original host, and the `PostgreSQL` and `MySQL`/`MariaDB` drivers verify the certificate against it through a private local socket bridge. Windows still refuses it. ADR-0019.
- RSA without the `rsa` crate (RUSTSEC-2023-0071 stays out of the tree, no advisory ignore): RSA SSH user keys (OpenSSH, PKCS#1, PKCS#8; 2048/3072/4096 bits; `rsa-sha2-256`/`-512`) through a `ring` signer in `sqler-tunnel`, and the `MySQL` plaintext RSA password exchange (`caching_sha2_password` cold cache, `sha256_password`) through a vendored `sqlx-mysql` 0.9.0 patch pinned `=0.9.0` that encrypts with `aws-lc-rs`. Limits: no SHA-1 `ssh-rsa`, no RSA-only host keys, legacy-encrypted PEM refused; the plaintext exchange runs only with an explicit `ssl-mode=disabled` (never as a `prefer` fallback, so a stripped TLS offer cannot downgrade), and even then it is open to a man-in-the-middle: only `require`/`verify-ca`/`verify-full` protect the password. `deny.toml` bans the `rsa` crate; `check-spdx.sh` skips `vendor/`. New `ssh` container tests (`start-sshd.sh`, gate id `ssh`) and a MySQL cold-cache test in the CI `db` job. `TunnelError::UnsupportedKeyType` is removed, and the committed test RSA keys under `crates/sqler-tunnel/tests/fixtures/` are gone (tests generate keys with `ssh-keygen`). ADR-0018; ADR-0010 and ADR-0013 point to it.
- SQL text services in `sqler-sql`, all pure and built on one hand-written, dialect-aware lexer that never fails: `split` and `statement_at` (exact byte ranges; strings, comments, dollar quotes, `BEGIN ... END` bodies and `MySQL` `DELIMITER` handled), `placeholders` (`$1`, `?`, `?1`, `:name`, `@name`, `$name` per dialect), fail-safe `classify`/`classify_each` (`Read` only when no write syntax, executable comment or non-allowlisted function is found) and an idempotent, comment-preserving `format`. No new dependencies. ADR-0020 (own lexer instead of `sqlparser`; `AGENTS.md` §2 updated) and the architecture page "SQL text services".
