## [Unreleased]

### Added

- Release pipeline (ADR-0064, R1): `release.yml` and `dist-workspace.toml` build `sqler-app` with cargo-dist for macOS, Windows and Linux (shell, PowerShell and MSI installers, SHA-256 checksums, a `DuckDB` guard before every upload), publishing only on a `v*` tag; new install page `user-guide/install.md`; the privacy note on the git history now gives counts only.
- Azure Data Studio importer (ADR-0067 amendment, R7): the new source `azure-data-studio` of `sqler-import` reads the user `settings.json` (`datasource.connections` and `datasource.connectionGroups`; `//` and `/* */` comments and trailing commas are accepted by a small bounded reader, no new dependency) from the per-OS default location or a given path. `MSSQL` entries map to the driver `sqlserver` with `sqlserver://<host>:<port>[/<db>]?user=<user>` (default port 1433; `host,port`, `tcp:` and IPv6 forms) and `PGSQL` entries to `postgres`; `encrypt` and `trustServerCertificate` map to the TLS mode (`verify-full`, `require`, `prefer`); the group tree and the nearest group colour are kept. Windows and Azure AD authentication, other providers and named instances are skipped with a reason (SQL login only, ADR-0071). Stored passwords are never read; the password is offered as a secret to enter. A `database` of `<default>` or empty means no database, and option names that look like a secret are not listed as unsupported. Same caps as the pgAdmin source. Real-file check by a maintainer is pending.
- Beekeeper Studio importer (ADR-0067 amendment, R8): `sqler-import` reads the JSON connection export of Beekeeper Studio and maps PostgreSQL, MySQL/MariaDB, SQLite and SQL Server connections (host, port, database, user, TLS, colour, folder, SSH tunnel); other engines are skipped and listed with a reason. Beekeeper writes passwords into the export in plain text; they are never read, and the user is asked to enter them. The format is assumed from Beekeeper's public source; a check against a real export is pending. No new dependency.
- SQL Server keychain password and SSH tunnel (S5, ADR-0071 amendment 1): the connect pipeline now knows `sqlserver://` and `mssql://` (default port 1433), so the keychain password is put into the target (percent-encoded) and a connection can use an SSH tunnel (dial host `127.0.0.1:<port>`, the TLS name stays the original host; `verify-full` through a tunnel is still refused on Windows). A `?user=` in a stored target is moved into the userinfo. TLS for these targets comes only from the connection's TLS setting. The host-engine wrapper now also denies error text that contains the password. No container test goes through a tunnel; a real check through an SSH tunnel and against a real SQL Server instance is pending (maintainer). Guides: `user-guide/databases/sqlserver.md`, `plugin-development/drivers.md`.
- Connection import core (ADR-0067, R6): the new L2 crate `sqler-import` reads a foreign connection file in three pure stages, `Source::parse` (bounded buffer, per-tool), `plan` (dry run against the store and the caller's driver list: skips, duplicates, `(2)` renames) and `apply` (adds only new connections and groups, never overwrites). pgAdmin `servers.json` is the first source (host, port, database, user, TLS mode and file paths, colour, SSH tunnel); every other field is listed by name as unsupported. No foreign secret value is imported: a needed secret is reported and is stored in the keychain only when the user enters it. Caps: 4 MiB file, 5,000 entries, 4,096 characters per field, 8 group levels; foreign paths are validated and never opened. No new third-party dependency. The import dialog is R9.
- Update signing key (ADR-0066 note, R17): the production Ed25519 public key (key id `efe45a1253fd9347`) is committed in `crates/sqler-update/keys/` and compiled into `sqler-update`, so update checks are configured; the private key lives only in the secret `SQLER_UPDATE_SIGNING_KEY` of the `release` environment. New tests tie the embedded key to its file name and key id; `docs/src/releasing/update-feed.md` records the fingerprint.
- Update check client (ADR-0066, R3): the new crate `sqler-update` (layer L1) fetches one Ed25519-signed manifest from the GitHub Releases `latest/download` asset `sqler-update.json`, verifies it with `ring` and reports `UpToDate` or a newer version with the notes link and the download entry for the platform. It is check-only (it never downloads or installs a binary), sends only a `GET` with the user agent `SQLer/<version> (update-check)`, caps the body at 64 KiB, follows at most 3 redirects and never from `https` to `http`. A pure schedule (first check 30 s after start, then every 24 h, backoff from 1 h to 24 h on failure) is included for the settings work. No public key is committed yet, so `check()` returns `NotConfigured` without a request until the release work adds it. Not linked into the app yet.
- M6 close (P17): ADR-0063 records, per engine, that SQL Server and `DuckDB` stay plugins over host-provided engines (the WASI guest route is NO-GO, ADR-0054), lists the API gaps (no T-SQL dialect so every `prod` statement confirms, `rows_affected` `None` so inline editing cannot apply on SQL Server, the `DuckDB` gaps G1 to G7) and what a promotion to a core crate would need; `DuckDB` is documented as not in 1.0. `docs/reports/iteration-007.md` lists the M6 items with PRs and docs, ADR-0054 to ADR-0063 and 0068 to 0072, the measured metrics, the `plugins-*` screenshots, the Definition of Done checks, the risks and the M7 plan. `docs/src/benchmarks.md` has the M6 row and note (binary size per OS against 73,400,320 bytes, plugin host delta, cold start, idle RSS, test count, benches).
- DuckDB engine, disabled and not in 1.0 (ADR-0070, P15 and amendment 2): the declarative plugin `plugins/duckdb` (host driver, capability `driver.host:duckdb`, no component) and the native engine `sqler-driver-duckdb` behind the new feature `driver-duckdb` of `sqler-app` and `sqler-cli` (off by default, implies `plugins`). Targets are `:memory:` or a file path; external file access and extensions are off. The plugin API gaps found (no dialect consumer, no read-only statement, no nested values, no per-file sharing helper, grants do not cover engine sandboxes) are written up in `plugin-development/drivers.md`. DuckDB is not part of version 1.0: the feature is never in a release artifact, installer or update manifest, and it may return after 1.0 as a separate download.
- Plugin template and developer docs (P14): `plugins/template` is a `cargo generate` template for a standalone `ui-plugin` crate (one command, one status item, no capability) that builds with `cargo build --release --target wasm32-wasip2` and installs by copying `sqler.toml` and the component to `<config>/plugins/<id>`. The `plugins` CI job generates the template and builds it. New pages `plugin-development/tutorial.md`, `wit-reference.md` and `publishing.md` (local install only; a registry is post-1.0). Two xtask tests, `template` and `wit_reference`, fail when the template's WIT copy, toolchain or `wit-bindgen` pin drift from the repo, or when the reference page and the WIT package disagree. No WIT change.
- SQL Server as an in-repo plugin with a host-provided engine (ADR-0071, P16): the new crate `sqler-driver-mssql` (`tiberius` 0.13 with `rustls` and the `ring` provider; SQL login only; `sqlserver://` target, `mssql://` alias) is linked only into builds with the new default-off feature `driver-mssql` of `sqler-app` and `sqler-cli` (it implies `plugins`), behind the declarative plugin `plugins/sqlserver` (capability `driver.host:mssql`, staged by `xtask`). TLS: `prefer` and `require` encrypt without checking the certificate, `verify-full` checks the chain and the host name (also with `server_name`), `verify-ca` and client certificates are refused. Cancel closes the connection (the next statement of that session says to connect again). Object browser from the `sys.*` views (current database only). The scrub of plugin error text learns the SQL Server wording and also covers the native engine's errors. Date and timestamp parameters are bound as `YYYYMMDD` and ISO 8601 with `T`, so a session `DATEFORMAT` does not change them. API gaps, not fixed here: no T-SQL dialect (a production connection confirms every statement), no keychain password and no SSH tunnel for `sqlserver://`, `rows_affected` is not reported, `net` scopes do not apply to host engines. The default binary has no `tiberius` (the CI `deny` job asserts it). `ring` is installed as the rustls process default at the start of both binaries when the feature is on, because `aws-lc-rs` is compiled in beside it (a `sqlx` verify-ca connection panicked without that during the check). Size, macOS release `sqler` with `plugins`: 49,757,680 bytes; with `plugins,driver-mssql`: 50,834,208 bytes (+1,076,528), both under the 73,400,320 byte budget. `cargo deny check` passes with no exception. Container tests run in CI (`db` job, SQL Server 2022); a run against a real SQL Server instance is pending (maintainer). Guide: `user-guide/databases/sqlserver.md`, `plugin-development/drivers.md`.
- Example plugins (P13): `plugins/hello-panel` (a panel, a command and a status item; the panel is opened by the app-generated panel command, ADR-0060) and `plugins/exporter-markdown` (an aligned Markdown table exporter, format id `plugin-exporter-markdown:markdown` under ADR-0072; number columns are right-aligned, which the built-in Markdown format does not do). Both are built by `xtask plugins build`, checked by `xtask plugins check` and tested against the host in `crates/sqler-plugin-host/tests/guests/`. New screenshot scene `plugins-hello-panel` (light and dark). No WIT change. Known gaps for P17: a command cannot show or focus a panel, and `exporter.start` cannot return leading bytes and gets no export options.
- Plugin completion providers (ADR-0026 note, P11): a plugin with a `[completion]` block (optional `drivers` list) adds rows to the SQL editor popup. The host has a typed `complete` call (250 ms deadline, items cleaned to one line and capped at 50 per answer, timeouts and traps count as faults) and a `completer` fixture plugin; the editor asks plugins off the UI thread and never waits for them, so the built-in popup is unchanged and the plugin rows (marked with the plugin name, after the built-in rows, at most 100) are merged when they arrive at the same place. The app allows one call per plugin in flight and skips a busy plugin and asks it again when its call ends. New page `plugin-development/completion.md`.
- Plugin export formats (ADR-0072, P10): a plugin that declares `[[exporters]]` adds a file format to **Export Results...** and to `sqler-cli export --format plugin-<id>:<fmt>`. The formats enter through a run-time `FormatSource` overlay on the export registry (`Registry::with_sources`; built-ins first, a taken id is skipped), so a plugin found after the first frame is listed without a restart; the dialog snapshots the registry when it opens and the snapshot travels in `WriteSpec`. The plugin returns bytes, SQLer writes them through the partial-file protocol, so a cancelled or failed export leaves no file. Labels are `<plugin name> (plugin): <label>` and cleaned; failures give fixed texts (crashed, did not answer in time, out of memory, stopped, not available, or the plugin's own one-line message); `ExportError::Plugin` is new. Cancel can lag by up to one plugin call (5 s). Plugin strings are interned (leaked once per distinct value). No WIT change; new fixture `plugins/fixtures/exporter` and bench `plugin_export`. Needs the `plugins` feature of `sqler-app` or `sqler-cli`. Guide: `plugin-development/exporters.md`.
- Plugin AI tools (ADR-0062, P12): a plugin with `ai.tool` now offers its manifest tools to the AI session, the agent endpoint and the in-app MCP server as `<plugin-id>__<tool-name>`. `sqler-ai-tools` gets the `ExternalTools` seam (listing filter, schema-subset argument check, `ExternalContext::approve` through the surface's own approver; one exit, so redaction, the untrusted envelope, the audit row and the cancel guard apply); `sqler-plugin-host` gets `ai_tools()` and a typed `invoke_ai_tool` that lends each call its own data service and approver; `sqler-app` (feature `plugins`, off by default) adapts the two, shows the plugin only the connections the surface lends, applies the surface's read-only flag and refuses statements with bound parameters that need approval. Redaction now also masks `columns` given as plain names. A surface without an audit sink offers no plugin tools; `sqler-cli mcp` lists none. New `ai-probe` test plugin.
- Plugin contributions in the window (ADR-0060 addendum, P8): the manifest's commands, panels and status items now show up. Palette commands have ids `plugin-<plugin>:<command>` (menu entries `object-plugin-...`, `editor-plugin-...`, `results-plugin-...`, panels `panel-plugin-...`), all rebindable in `keybindings.toml`; the object menu (Shift+F10) lists plugin entries; status items sit in the status bar; a **Plugins** bottom tab (`workbench:show-plugin-panels`, `"plugin-panels"` in `workbench.toml`) renders panel widget trees with an error state and **Reload**. Contributions of a plugin that is off, faulted, failed or not approved are removed. The host gets the real `ui` import (declared items only, `ui.panel` for panels, per-plugin rate limits, one-line capped texts) and typed `run_command`, `render_panel`, `panel_event` and `status` calls instead of the removed `ui_seam`. `PluginsBackend` gains four future methods and `PluginsStartup::ui_events`. The `sqler-plugin-api` command id helper now returns `plugin-<id>:<cmd>`. No WIT change. User guide: "What plugins add".
- Plugins in the workbench (ADR-0060, P7): the app feature `plugins` (off by default; `cl` engine and HTTP egress) wires the plugin host behind the `PluginsBackend` trait of `sqler-ui`, so `sqler-ui` stays free of wasmtime. The first scan starts after the first frame, plugins run on their own tokio runtime, and development paths come only from the repeatable `--plugin-dir <PATH>` flag (never `target/plugins`). The data folder `plugins/<id>/data` is created as a real directory and a pre-placed link is refused. Preferences (plugins switched off, setting values) are kept in `plugin-prefs.toml`. Plugin writes are approved in a dialog of the workbench that names the plugin (name and id), the connection and the exact statement; Deny is the default focus, Approve takes pointer clicks only (no key, not a tab stop) and is ignored for about half a second after the dialog appears, and a production connection adds the query editor's production confirmation on the same SQL; a dropped or closed question is a denial. `db.read` is now a flagged permission in the grant dialog and the Plugins list (it sends data to the plugin, and with `net.http` possibly further). The Plugins view, its commands, the keyboard way to approve a plugin grant (type the plugin id) and the size figures are in the user guide and the ADR.
- Plugin `query` and `catalog` interfaces (ADR-0058, P5): `sqler-plugin-host` (feature `cl` / `pulley-rt`) now answers `catalog` (connections, objects, columns; `db.read`) and `query.run` instead of the gate-checked stubs. The host classifies every statement (fail-safe), runs one statement per call, and asks for approval of the exact SQL and params for anything but a plain read (`db.write`, twice on `prod`, never on a read-only connection); caps for SQL size, params, rows, 8 MiB of result and time; a dropped call cancels and releases the lent session. The app supplies connections and the dialog through the new `DataService` and `QueryApprover` traits (`PluginData` in `Services`). Plugin output is not AI-redacted, and `db.read` with `net.http` may send data to that host. No streaming: plugins page with `LIMIT`/`OFFSET`.
- Plugin drivers (ADR-0061, P9): a plugin can provide a database driver, either a guest driver (a WebAssembly component under `driver.guest`) or a host driver (a declarative shell around a native engine, `driver.host:<engine>`). Drivers enter the registry through a run-time `DriverSource` overlay (built-ins first, `Driver::id` returns `&str`, `DriverError::Unavailable`), so enable, disable and revoke take effect at the next lookup; the WIT package is 0.1.1 with the optional `driver-catalog` interface. A guest driver receives the host, username and password of every connection that uses its driver and nothing else (no SSH secret, TLS paths or other connections); the run flow and the production gate apply unchanged and a plugin driver has no write path of its own. Unavailable drivers show fixed texts. The grant dialog line for `driver.guest` now says that the plugin receives the host, username and password of every connection that uses its driver. The connection form refreshes its driver list when the Plugins view changes something (`Workspace::set_drivers`). Needs the `plugins` feature of `sqler-app` or `sqler-cli` (both off by default); the CLI reads `<config>/plugins` and the stored approvals and never prompts. Guide: `plugin-development/drivers.md`.
- Plugin capability grants (ADR-0059): approvals are stored in `plugin-grants.toml` (mode 0600 on Unix), keyed by plugin id, version, manifest hash and component hash; Approve is all-or-nothing, Deny and Escape (pressed anywhere in the dialog) are remembered, only a pointer click on the Approve button approves (no key, not a tab stop; keyboard-only users can Deny, or type the plugin id into the field and press Enter to approve), the dialog shows a summary and, as a chip, every permission that needs attention (every web host, folder, `db.read`, `db.write`, AI tool and driver; only `ui.panel` is quiet) outside the scroll area, the prompt cannot be forged (private fields, key and capabilities derived from the manifest) and a decision is refused when another instance changed the plugin's record meanwhile, plugin names are stripped of invisible format characters, writes use a unique temporary file name, a change reloads the file so another instance's denial is kept, and a damaged, newer or other-writable file denies everything without being rewritten. User guide: `user-guide/plugins.md`.

The `plugins` limit (budget minus 1 MiB) is 82,837,504 bytes. `size.yml` (still report only) compares against 83,886,080; `AGENTS.md`, `docs/src/benchmarks.md`, the DuckDB size paragraph of the driver guide and the status lines of ADR-0001, 0009, 0029, 0032, 0054, 0057 and 0060 carry the new figure. The `default` features are not changed.
- CI: no pull request job compiles the bundled DuckDB C++ engine any more (ADR-0070, amendment 2). Workspace jobs use `--workspace --exclude sqler-driver-duckdb` and an explicit feature list (`WS_FEATURES` in `ci.yml`, checked by the `deny` job) instead of `--all-features`; the new `duckdb` job builds and tests the engine only on a manual `workflow_dispatch` (`gh workflow run ci.yml --ref <branch>`), never on pull requests or `main`. The `deny` graph still includes the DuckDB dependency tree.
- Binary size budget raised from 60 MB to 70 MB (73,400,320 bytes), the owner's decision of 2026-10-23 (ADR-0069): the Linux release binary was 62,521,192 bytes with about 0.4 MB of headroom, and the plugin host and the AI stack need room. `size.yml` (still report only) now compares against 73,400,320 bytes and prints the per-OS sizes as before; `AGENTS.md` and `docs/src/benchmarks.md` carry the new figure, and older ADRs have a dated "Superseded in part by" line. The `plugins` feature stays off by default. There is no size threshold in `xtask` to change.
- CI speed-up (ADR-0068): `ci.yml` has a `changes` job (`dorny/paths-filter`) that gates the Rust, UI, database, plugin and rustdoc work by path while every check name keeps reporting; a new `CI result` check fails when any CI job failed or was cancelled; caches are saved on `main` only (PRs restore), with a shared `debug` key and no cache for `deny`; Windows clippy is its own job `clippy (windows-latest)` and a Windows PR builds and tests the crates with a Windows-only history and a macOS PR skips the platform-agnostic crates (full suite on every OS on `main`, on dispatch and with the label `full-ci`); apt steps retry and time out instead of stalling; a new push cancels only PR runs, never `main`; `CARGO_PROFILE_DEV_DEBUG=line-tables-only` in CI. `bench.yml` also runs on `main` and only for PRs that touch what it builds, `size.yml` measures Linux only on PRs, `spike.yml` and `plugin-spike.yml` no longer run twice for a PR branch. New `.github/scripts/ci-timings.sh`. Timings in `docs/src/benchmarks.md`.
- M5 metrics and iteration-006 report: `docs/reports/iteration-006.md` lists the M5 (AI) items with PR numbers, ADR-0034 to ADR-0041 and ADR-0050 to ADR-0053, the screenshots of the `ai-*` and `agent-*` scenes (re-captured at `6ed581c`, byte-identical), the Definition of Done checks, the risks and the M6 plan. `docs/src/benchmarks.md` has the M5 measurements: Linux release binary 62,512,360 bytes (59.6 MiB, 402,200 bytes under the 60 MB budget), macOS 37,798,480, Windows 49,543,680; 3385 tests; cold start about 137 to 144 ms and idle RSS about 104 MiB with three sessions open on macOS. AGENTS.md section 9 marks M5 done and M6 next and lists the consolidated pending maintainer checks.
- Component restyle (M4.5, ADR-0043): every view uses the design tokens and the shared chrome (`workspace::chrome`: row heights, list-row states, dialog frame, scrim) instead of literal sizes and colours, and Lucide icons instead of text glyphs. The object browser has 24 px rows with kind icons, chevrons, hover/selected/focus states, tooltips and a "No connections yet" empty state with a **New Connection** button; the command palette shows shortcuts as key chips and a "Recently used" section above "All commands"; connection, drop, parameter, confirm, export, edit-SQL and history dialogs share one frame; the grid header, cells (mono face), toolbar and filter bar use the tokens; menus and tooltips show shortcut hints; History and Saved Queries have empty states with icons. Button texts, command IDs and key bindings are unchanged. A source guard (`tests/view_tokens.rs`) fails on hard-coded spacing, type sizes, radii and colours in the restyled views. The 12 screenshot scenes are refreshed in both themes.
- `grid_viewport` benchmark: new `--staged N` option (CI passes 10000) stages N cell edits on the 1,000,000-row grid and times the display path with edits pending (`staged_p50_ns`, `staged_p95_ns`, `staged_stage_ms`); `staged_p95_ns` is held to the 1 ms budget and compared against the baseline only when the baseline file has the key. `bench.yml` passes the flag to the base only if the base bench knows it.
- Linux release binary of `sqler` under the 60 MB budget: `[profile.release]` now has `strip = "symbols"` (the ELF symbol table was about 23 MB of 78 MB; macOS and Windows keep symbols in side files) and `codegen-units = 1` (about 9 MB less, release build about 1.7x slower). Release backtraces show addresses, not function names (AGENTS.md section 10). `size.yml` also prints the largest sections (`size -A`) on Linux, and the largest crates (`cargo bloat --crates`, from a separate unstripped build) on push to `main` and manual runs only, not on pull requests; report only. Measurements in `docs/src/benchmarks.md`.
- Result grids are bounded (ADR-0027): a result loads one page at a time (`result_page_rows` in `settings.toml`, default 100,000, range 1,000 to 10,000,000, or 64 MiB of cells) and then pauses with `N rows loaded; more rows available`. The new **Fetch more** button and `grid:fetch-more` command load the next page; Cancel or closing the tab ends a paused result. A paused statement holds the tab session, so later statements of a script stay pending until fetch-all or cancel. Rows are stored in a compact per-batch layout (new `GridLimits`, `GridCancel`, `RowRef`, `CellRef`; the read API no longer returns `&Row`); the synthetic grid, the `grid_viewport` bench and `grid_scroll` stay unbounded. Figures in `docs/src/benchmarks.md`.
- `grid_viewport` and `browser_tree` benchmarks gate on the minimum over `--reps` (3) repetitions with an absolute `--slack-ns` (100 ns and 250 us), so noise on shared CI runners no longer fails unrelated pull requests; a 2x slowdown still fails. `bench.yml` and `docs/src/benchmarks.md` updated.
- `Bench` workflow no longer flakes on the browser tree: base and PR rounds alternate in one job step (8 rounds for `browser_tree`, 6 for `grid_viewport`) and a judge-only call compares the minimum per side, `browser_tree` gates on the expand p50 (25 % + 250 us, 1 ms floor) after a 30-iteration warm-up and only warns on the p95, and both benches gain `--pr` and a repeatable `--compare`; a simulated 2x expand slowdown (`--simulate-slowdown`) still fails. Noise analysis in `docs/src/benchmarks.md`.

### Fixed

- Security: `ctutils` 0.4.3 to 0.4.4 in `Cargo.lock` (RUSTSEC-2026-0385, non-constant-time mask generation and u128 comparisons); `cargo deny check` passes again. No advisory ignore was added.
- Four timing-sensitive tests no longer flake. The guard suite (`s2`, `s8`) runs every scenario except the time-limit one with a 25 s tool time limit instead of 1 s, so a slow runner that needs more than a second to open the session cannot cut a write short; the AI session test that cancels a running statement accepts both orders in which the session and the driver cancel are seen; the plugin host tests create their `tracing` dispatcher before any host event, so the log flood test cannot capture nothing.
- AI audit guarantee (ADR-0037 addendum): the AI session tab, the Agent tab and the editor AI actions no longer run tool calls unaudited when the app has no audit sink. They now refuse to start and show "AI is off: SQLer found no config folder for the AI audit log, and every AI tool call must be audited." This happens only when the platform gives no config folder; the three surfaces take their sink from one helper (`AiAudit`) so they cannot drift. A sink that cannot write still fails open.
- AI permission card (ADR-0051 addendum): title, kind, option names and tool text are cut to the transcript entry cap, and at most 8 requests wait; more are cancelled at once.
- AI assist budgets (ADR-0038 addendum) come from the room left after the fixed part, so a pasted statement on a small context window no longer overflows the window; `SqlAnswer.applicable` is false for SQL with a redaction placeholder and the editor actions do not insert it.
- AI session engine transcript is capped at 500 entries (ADR-0039 addendum) with stable entry numbers (ADR-0053 addendum).
- AI providers: Anthropic and Ollama streams time out after 120 s of silence, `Retry-After` is clamped to 1 hour, and parse errors no longer quote server data.

- MCP over HTTP: an `initialize` without `protocolVersion` no longer takes one of the 64 session slots (it is answered with `-32602` and no session). The `--token-file` permissions (mode 0600, refusal of a file readable by others) are Unix only; the docs and `--help` now say that Windows uses the directory ACL.

- Editing a connection no longer drops its `[connection.ai]` opt-in.
- Editor: the bracket-match observer no longer resets the bracket frames when they already hold the wanted ranges. This ends a notify loop of the observer (frames set, state notified, observer run again) that hung a headless window, and it compares the frames the collection holds, so an edit that deforms the anchored frames still gets them reset.
- `MySQL`/`MariaDB` driver: a single `USE` statement runs over the text protocol; a repeated `USE` on `MariaDB` now switches the database instead of being answered from the prepared-statement cache.
- `sqler-completion` diagnostics: `RETURNING` of an `INSERT ... SELECT` no longer reports `AmbiguousColumn` (it sees the insert target only); `pg_temp`, `pg_temp_N` and `pg_toast_temp_N` are PostgreSQL system schemas; `public.users.id` matches `FROM users`; `DELIMITER` is a client command only at the start of a line; a routine without a custom `DELIMITER` ends at its own `;` so later statements are still checked, and nothing inside a routine definition is reported; `SET` target detection is linear (a 32,000-branch `CASE` update no longer takes seconds). The completion bench reports the minimum over repetitions for `hover_p95_ns` and `diagnose_p95_ns` too.

### Added

- Plugin host runtime (P4, ADR-0057): `sqler-plugin-host` discovers plugins and checks manifests, computes the component digest and grant key, and resolves `fs.read` scopes without wasmtime (default features). Features `cl` / `pulley-rt` add the wasmtime 50.0.0 runtime: one store per plugin, epoch-based deadlines and cancel, a memory cap, trap/panic/OOM/timeout isolation, three consecutive faults disable a plugin, WASI without env, args, stdin or sockets and with read-only preopens for approved scopes (clocks and random stay linked), rate-limited sanitised logs. Feature `net` adds `NetEgress` for plugin HTTP (granted host and port, trailing dot stripped, punycode kept, vetted resolver against DNS rebinding, no proxy, no redirects, 8 MiB request and 16 MiB response caps, 4 requests and 32 MiB in flight per plugin, 16 and 96 MiB per host, refused with `connection-limit-reached`). An apply is refused while the query tab is inside a transaction you opened (the app tracks `BEGIN`, `START TRANSACTION`, `SAVEPOINT` and `SET autocommit = 0` and errs toward refusing; after `MySQL` `SET autocommit = 0` only `SET autocommit = 1` clears it), a query with pending changes is not run again, and closing a tab or quitting with pending changes asks first. After each eligible single-table `SELECT` SQLer runs one extra read-only catalog statement on the same session (the schema probe). Binary cells are read-only (hex editing is deferred). Commands `grid:edit-cell`, `grid:set-null`, `grid:revert-selection`, `grid:add-row`, `grid:delete-rows`, `grid:preview-changes`, `grid:apply-changes`, `grid:discard-changes`, `grid:edit-without-key` have no default shortcut (`Mod+S` and `Mod+Shift+S` are left free on purpose). Known limits: on `SQLite` a `NaN` becomes `NULL`, on `MySQL` a `DATETIME` loses its offset, concurrent changes are overwritten (last writer wins), a domain over `bit(n)` may cut silently, and `PostgreSQL` `interval` and `"char"` columns are read-only.
