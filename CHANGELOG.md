# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed

- `grid_viewport` benchmark: new `--staged N` option (CI passes 10000) stages N cell edits on the 1,000,000-row grid and times the display path with edits pending (`staged_p50_ns`, `staged_p95_ns`, `staged_stage_ms`); `staged_p95_ns` is held to the 1 ms budget and compared against the baseline only when the baseline file has the key. `bench.yml` passes the flag to the base only if the base bench knows it.
- Linux release binary of `sqler` under the 60 MB budget: `[profile.release]` now has `strip = "symbols"` (the ELF symbol table was about 23 MB of 78 MB; macOS and Windows keep symbols in side files) and `codegen-units = 1` (about 9 MB less, release build about 1.7x slower). Release backtraces show addresses, not function names (AGENTS.md section 10). `size.yml` also prints the largest sections (`size -A`) on Linux, and the largest crates (`cargo bloat --crates`, from a separate unstripped build) on push to `main` and manual runs only, not on pull requests; report only. Measurements in `docs/src/benchmarks.md`.
- Result grids are bounded (ADR-0027): a result loads one page at a time (`result_page_rows` in `settings.toml`, default 100,000, range 1,000 to 10,000,000, or 64 MiB of cells) and then pauses with `N rows loaded; more rows available`. The new **Fetch more** button and `grid:fetch-more` command load the next page; Cancel or closing the tab ends a paused result. A paused statement holds the tab session, so later statements of a script stay pending until fetch-all or cancel. Rows are stored in a compact per-batch layout (new `GridLimits`, `GridCancel`, `RowRef`, `CellRef`; the read API no longer returns `&Row`); the synthetic grid, the `grid_viewport` bench and `grid_scroll` stay unbounded. Figures in `docs/src/benchmarks.md`.
- `grid_viewport` and `browser_tree` benchmarks gate on the minimum over `--reps` (3) repetitions with an absolute `--slack-ns` (100 ns and 250 us), so noise on shared CI runners no longer fails unrelated pull requests; a 2x slowdown still fails. `bench.yml` and `docs/src/benchmarks.md` updated.
- `Bench` workflow no longer flakes on the browser tree: base and PR rounds alternate in one job step (8 rounds for `browser_tree`, 6 for `grid_viewport`) and a judge-only call compares the minimum per side, `browser_tree` gates on the expand p50 (25 % + 250 us, 1 ms floor) after a 30-iteration warm-up and only warns on the p95, and both benches gain `--pr` and a repeatable `--compare`; a simulated 2x expand slowdown (`--simulate-slowdown`) still fails. Noise analysis in `docs/src/benchmarks.md`.

### Fixed

- Editor: the bracket-match observer no longer resets the bracket frames when they already hold the wanted ranges. This ends a notify loop of the observer (frames set, state notified, observer run again) that hung a headless window, and it compares the frames the collection holds, so an edit that deforms the anchored frames still gets them reset.
- `MySQL`/`MariaDB` driver: a single `USE` statement runs over the text protocol; a repeated `USE` on `MariaDB` now switches the database instead of being answered from the prepared-statement cache.
- `sqler-completion` diagnostics: `RETURNING` of an `INSERT ... SELECT` no longer reports `AmbiguousColumn` (it sees the insert target only); `pg_temp`, `pg_temp_N` and `pg_toast_temp_N` are PostgreSQL system schemas; `public.users.id` matches `FROM users`; `DELIMITER` is a client command only at the start of a line; a routine without a custom `DELIMITER` ends at its own `;` so later statements are still checked, and nothing inside a routine definition is reported; `SET` target detection is linear (a 32,000-branch `CASE` update no longer takes seconds). The completion bench reports the minimum over repetitions for `hover_p95_ns` and `diagnose_p95_ns` too.

- M4 metrics and the iteration-005 report: `docs/reports/iteration-005.md` and the M4 row, note and re-run lines in `docs/src/benchmarks.md`, measured at `ec3057c` on macOS arm64 (cold start 133.7 ms, idle RSS 72.1 to 101.4 MiB with three sessions open, binary 30.46 MiB; `size.yml`: Linux 55,798,352, macOS 31,922,960, Windows 40,875,520 bytes; 2237 tests passed; 1M-row grid heap 108.62 MiB), the new `grid_copy` section, the M4 pending maintainer checks and known limits in `AGENTS.md` section 9, three M4 gotchas in section 10, and roadmap status M4 done. Unexplained changes (cold start +20 ms, `hover_p95_ns` +20 %, two high idle RSS runs, one high `editor_buffer` bracket build) are reported, not hidden.
- Cell detail pane in the results grid: `grid:toggle-cell-detail` ("Results: Toggle Cell Detail", no default chord because Mod+Shift+I is the GPUI inspector on Linux and Windows) opens a resizable pane to the right of the table with the full value of the active cell: column, type, size in bytes, NULL marker; text as stored (tabs and control characters made visible, long lines continued), JSON indented without reordering keys or changing numbers (invalid JSON, JSON nested at depth 128 or deeper, and JSON over 8 MiB are shown as stored with a note), binary as a hex dump. At most 1 MiB is shown, with a note; **Show all** loads the rest on the background executor, and **Copy value** copies the full value as plain text. New headless `sqler_ui::grid::CellDetail` with insta snapshots; `sqler-ui` now depends on `serde` and `serde_json` (and `insta` for tests). `grid_viewport` unchanged.
- Copy from the results grid: Mod+C (`grid:copy`) copies the selection as tab-separated text, Mod+Shift+C (`grid:copy-with-headers`) adds the column names, and `grid:copy-as-markdown`, `grid:copy-as-json` and `grid:copy-as-insert` copy a Markdown table, JSON or SQL `INSERT` statements, all in the palette and in the menu of a right click on a table row. The text is rendered by the `sqler-export` writers in the grid's column and row order; `INSERT` uses the connection's dialect and, for an open-data tab, the real table name (else `table_name`; PostgreSQL quoting with a notice when the connection has no dialect). A copy is limited to 1,000,000 cells and 50 MiB, large selections are read in slices and rendered in the background, and a partial result says that only the fetched rows were copied. New headless module `sqler_ui::grid::copy` (no GPUI), `grid_copy` benchmark, `sqler-export` as a dependency of `sqler-ui` (no features). Mod+C is claimed only while a results table has the focus; the SQL editor's copy and `keymap.rs` defaults are unchanged.
- Results grid sort and filter (ADR-0031): a sort indicator in each column header (click cycles ascending, descending, none; Shift+click adds a key; numbered for several keys), the commands `grid:sort-ascending`, `grid:sort-descending`, `grid:clear-sort`, `grid:clear-filter` and `grid:toggle-match-case`, and a filter bar with a quick filter (all columns or one), per-column conditions (equals, not equals, contains, greater, less, is NULL, is not NULL) combined with AND, "N of M rows" in the status and a match-case switch. They act on the rows the grid holds ("loaded rows only" while loading or paused), put NULL last in both directions, merge arriving rows in, and run in short slices on the interface thread (a new sort or filter supersedes the running one; decimals have an ordered key, and the sorted runs are sized from the measured speed so a step stays bounded). Headless in `sqler_ui::grid` (`SortSpec`, `FilterSpec`, `GridOrder`, `DisplayRows`); `GridControls::{apply, click_cell, click_header, is_selected, motion_moves}` now take a `&dyn RowOrder` (pass `&tab.rows()`) and `Applied.scroll_row` is a display row. The new `grid_sort` bench is described in `docs/src/benchmarks.md`.
- Export from the results grid (ADR-0032): **Export Results...** (`grid:export`) writes a table-data tab or any query result to CSV, JSON, SQL `INSERT`, Markdown, Excel or Parquet. Scope: the loaded rows, the selected cells in display order, or all rows by running the statement again on a new session (only for one statement classified as a read; a write, DDL, a script or an unclassified statement is never run a second time and only the loaded rows are offered). Options per format (CSV delimiter, header, NULL text; Markdown NULL text; SQL table, schema, rows per `INSERT`), the system save dialog, a progress line with **Cancel** (`export:cancel`). The writer runs on the blocking pool behind a bounded 4-batch feed, so memory does not depend on the row count; the file is written under a hidden name and renamed when complete, so a failed or cancelled export leaves nothing behind; an export is refused if the result changed while its dialog was open. New public module `sqler_ui::export` (headless; `Feed`, `ExportStop`, `write_feed`, `fresh_rows`, `LoadedCursor`, `PartialFile`, `ExportFailure`), `grid_export` benchmark (loaded CSV 4.3 M rows/s, loaded Parquet 3.3 M, fresh `SQLite` CSV 0.86 M), user guide section and architecture page. `export-parquet` is now in the `sqler-app` default: the Linux release binary grows by 655,360 bytes on aarch64 (46,626,808 to 47,282,168) and 781,440 on x86_64 (54,165,824 to 54,947,264; limit 61,865,984), see ADR-0032; the `Binary size` run on the pull request is the final check.
- Inline editing in the results grid (ADR-0033): edit cells by double-click, Enter or F2 with an editor that suits the column type, set NULL, add and delete rows, see pending changes marked, preview the exact SQL (values listed apart from it), and apply everything in one transaction or discard it. Read-only unless the result is a plain single-table `SELECT` (or a table opened from the browser) with its full primary key; a table without a key needs an explicit opt-in. A `prod` connection asks for confirmation first ("Apply to production?"). An apply is refused while the query tab is inside a transaction you opened (the app tracks `BEGIN`, `START TRANSACTION`, `SAVEPOINT` and `SET autocommit = 0` and errs toward refusing; after `MySQL` `SET autocommit = 0` only `SET autocommit = 1` clears it), a query with pending changes is not run again, and closing a tab or quitting with pending changes asks first. After each eligible single-table `SELECT` SQLer runs one extra read-only catalog statement on the same session (the schema probe). Binary cells are read-only (hex editing is deferred). Commands `grid:edit-cell`, `grid:set-null`, `grid:revert-selection`, `grid:add-row`, `grid:delete-rows`, `grid:preview-changes`, `grid:apply-changes`, `grid:discard-changes`, `grid:edit-without-key` have no default shortcut (`Mod+S` and `Mod+Shift+S` are left free on purpose). Known limits: on `SQLite` a `NaN` becomes `NULL`, on `MySQL` a `DATETIME` loses its offset, concurrent changes are overwritten (last writer wins), a domain over `bit(n)` may cut silently, and `PostgreSQL` `interval` and `"char"` columns are read-only. User guide: Results grid, Editing.
- Results grid columns and selection: resize columns by dragging (double-click fits to content), move them by drag or `grid:move-column-left`/`-right`, pin and unpin (`grid:pin-column`, `grid:unpin-column`), `grid:autofit-column` and `grid:reset-layout`; click, Shift+click, header click and keyboard selection of cells, rows, columns and all cells (arrows, Home/End, Page Up/Down, Tab and Shift+Tab only while they move the active cell, Mod+A, Shift+Space, Ctrl+Space; Shift extends) while the grid has the focus, with 32 `grid:*` palette commands (the keys are routed to the grid before the global chords, only while a results table has the focus: Ctrl+Space selects the column there and still triggers completion in the editor; no default global chord was added). The layout and selection are per open table and headless in `sqler_ui::grid` (`ColumnLayout`, `Selection`, `GridControls`); `Selection::rect` gives the selected display range for copy and export. The `grid_viewport` benchmark prints `layout_*` keys (not gated). See "Results grid" in the keybindings page.
- `sqler-export`: `Parquet` (low-level `parquet` writer without `arrow`, row groups of 65,536 rows or 32 MiB, Snappy or none, `Decimal` as exact text, timestamps in microseconds, a zone stored as UTC) and `Excel` `.xlsx` (own streaming zip, one sheet, bold header, typed cells, dates as dates, text always an inline string so a formula is never written, `=`/`+`/`-`/`@` text carries a quote-prefix format, Excel limits give `ExportError::Limit`), behind the cargo features `parquet` and `xlsx` of `sqler-export` (default on there; `sqler-app` forwards `export-xlsx` in its default and `export-parquet` as opt-in). New `ParquetOptions`, `ParquetCompression`, `ExportError::{Limit, Unsupported, Encode}` and the ids `PARQUET` and `XLSX`. 1M-row memory test (`streaming_memory.rs`), `export_throughput --format`, ADR-0029 with measured size, compile and speed cost, an "Export writers" section in `docs/src/benchmarks.md`.
- `sqler-cli export`: streams the result of one statement into a `CSV`, `JSON`, `SQL` or Markdown file (`--format`, `--output` with `-` for stdout, `--table`, `--schema`), one batch at a time. The SQL is classified before connecting: only reads export, anything else is refused (exit 3) unless `--allow-write`, which prints only the statement class as a warning (never the SQL). Ctrl+C cancels (exit 130, `SIGTERM` exit 143; a second signal exits at once) and removes the partial file (written to a hidden sibling and renamed on success); formats compiled out are refused (exit 2). Exit codes documented in the CLI user guide. Error messages never repeat an argument and the text of driver errors is replaced by a fixed one per kind, so a URL in the wrong place cannot print its password.
- `sqler-export`: writers for `CSV` (RFC 4180; delimiter, header, `NULL` text, line ending, opt-in `neutralize_formulas`), `JSON` (array of objects, `JSON` columns embedded), `SQL` `INSERT` (dialect-quoted identifiers, literals per dialect, rows per statement) and Markdown tables, behind a push-style `RowWriter` API with a `Registry`, an `Exporter` (buffering, cancel, progress) and `export_to_vec`; 1M-row streaming test and `export_throughput` bench (ADR-0028)
- `sqler-sql`: `sql_literal`, `push_literal` and `string_literal` render a value as a SQL literal per dialect; the lexer (`tokenize`, `Token`, `TokenKind`) is public (ADR-0028)
- `sqler --open-sessions` (measurement option, next to `--exit-after-first-frame`): after startup it opens every saved connection through the normal connect pipeline (ADR-0016), logs one `sqler: open-sessions: ...` line per connection on stderr and idles, so the idle RSS with sessions open can be measured. SQLer itself never prompts (an SSH agent may) and prints no secret; skip lines hold the connection name and a fixed reason per failure kind (the error text is never printed, so no database target, credential or key path can leak); only the unknown and changed SSH host key reasons add the jump `host:port`: connections with a keychain secret, or an unknown or changed SSH host key, are skipped with a line. New `Binary size` workflow (`.github/workflows/size.yml`) builds `sqler-app --release --locked` on Linux, macOS and Windows (main, `workflow_dispatch`, PRs touching `crates/**`, `Cargo.toml`, `Cargo.lock`, `vendor/**`) and prints the size in bytes and MiB next to the 60 MB budget; report only, not a gate. `docs/src/benchmarks.md` and `AGENTS.md` §3 describe both methods.
- M3 metrics and the iteration-004 report: fresh cold start, idle RSS, binary size, completion, catalog index and editor benchmark figures in `docs/src/benchmarks.md` (new "SQL editor buffer" section), `docs/reports/iteration-004.md`, roadmap status M3 done.
- Intellisense in the SQL editor: completion while typing and on `editor:trigger-completion` (Ctrl+Space; on macOS the system may use it for input source switching, rebind it or use the palette), hover with column type, nullability and foreign key target, and underlined diagnostics 300 ms after typing, all from the connection's object browser catalog. Missing columns are loaded in the background and a catalog refresh updates suggestions without reopening the tab. New public module `sqler_ui::editor::intellisense` (no GPUI), direct dependency `lsp-types`, `editor_intellisense` benchmark, ADR-0026 and an "Intellisense" section in the SQL editor user guide and the UI architecture page. Limits: snippets are inserted without tab stops; a failed load is retried only after the browser reconnects.
- Query history and saved queries in the desktop app: every statement that finishes, fails or is cancelled in an editor is recorded in `history.jsonl` (SQL before binding, outcome, duration, row count; no error text or parameter values). `history:open` opens a History tab per connection with text search and an "All connections" filter, from which an entry is opened in an editor or run again (through query execution, so the `prod` confirmation still applies); `history:clear` deletes everything after a confirmation. `query:save` saves the editor text as a named query in `queries.toml`; saved queries are listed in a sidebar section and the `query:open-saved` picker, and can be renamed and deleted (with confirmation). All store access runs off the UI thread. New public module `sqler_ui::history` (no GPUI), `Startup.history_dir`, the user guide page "Query history and saved queries" and a section in the UI architecture page.
- Query execution in the desktop app: run the selection, the statement at the cursor or the whole script (`query:run-selection` Cmd/Ctrl+E, `query:run-statement` Cmd/Ctrl+Enter, `query:run-all` Cmd/Ctrl+Shift+Enter, `query:cancel` Cmd/Ctrl+.). Statements come from the `sqler-sql` splitter and stop at the first error; each result streams into its own grid with row count, duration or error, and the run can be cancelled on the server. Placeholders open a parameter dialog and are sent as bound parameters, never spliced into the SQL; cancelling the dialog runs nothing. On a `prod` connection every statement that is not a plain read needs one confirmation that shows its exact SQL, also inside run-all. New public module `sqler_ui::query` (no GPUI), ADR-0024 and the user guide page "Running queries".
- SQL editor tab in the desktop app: a code editor per connection (`gpui-component` editor, tree-sitter SQL highlighting for light and dark themes), header with connection name, colour and environment, multi-cursor editing (Alt-click, add cursor above or below, add next occurrence), bracket matching, `editor:format-sql` for the selection or the whole buffer as one undo step, `editor:new` (Cmd/Ctrl+N), `editor:go-to-matching-bracket`, "Open in SQL Editor" in the object browser and on DDL tabs, and `dev:open-large-sql-script` (10,000 lines). The editor logic is headless in `sqler_ui::editor`; the buffer is handed to query execution through the `RunPort` trait. New `editor_buffer` benchmark. ADR-0025, the user guide page "SQL editor" and an "SQL editor" section in the UI architecture page.
- `sqler-completion`: hover and diagnostics on the same scanner as completion. `hover(&HoverRequest, &dyn SchemaSource)` returns the column type, native type, nullability and foreign key target of the column under the cursor (direct, through an alias, through a bare table name or schema-qualified), the kind and schema of a table, view or materialized view (also through its alias), and the name of a CTE or subquery, `None` for keywords, literals and names it cannot resolve. `diagnose(text, dialect, &dyn SchemaSource)` reports unknown schemas, tables or views, columns and qualifiers as errors and ambiguous columns as warnings, with the byte range of the identifier and a message, per statement; it never flags names of relations whose columns or lists are not loaded, system schemas, tables created in the text, CTE columns it cannot name, or syntax the scanner does not model, or anything inside a stored routine definition (parameters and locals), and follows the dialect's quoting and case rules (`PostgreSQL` exact for quoted names). `SchemaSource` gains `foreign_keys` (default: none) and `MemorySchema` `add_foreign_key`. Property tests (never panics, ranges inside the text, schema-only text has no unknown identifiers), example tests, hover and diagnose scenarios in the `completion` benchmark (p95 well under the 16 ms budget on the 5,000-table schema) and the architecture section "Hover and diagnostics".
- `sqler-completion`: SQL completion engine for `PostgreSQL`, `MySQL`/`MariaDB` and `SQLite`. `complete(&CompletionRequest, &dyn SchemaSource)` is pure and synchronous, works on incomplete SQL (own total lexer, no `sqlparser`), detects the context (relation, select list, `WHERE`, `ON`, `GROUP BY`, `ORDER BY`, `schema.`, `alias.`, `INSERT` columns), resolves aliases, CTEs and subquery aliases with dialect-specific quoting and case rules, offers per-dialect keywords, built-in functions and five snippets, and ranks in-scope columns and prefix matches first. The schema is read through the `SchemaSource` trait over `sqler-core` types (`MemorySchema` for tests); columns that are not loaded produce a `SchemaRequest`, not an error. Proptest and snapshot tests, a 5,000-table `completion` benchmark (p95 budget 16 ms, also run by `bench.yml`), ADR-0023 (including the hover and diagnostics shape) and the architecture page "Completion engine".
- `sqler-catalog` snapshot and name index for intellisense: `Catalog::snapshot()` returns an immutable, `Send + Sync` `CatalogSnapshot` without waiting on the worker (copy-on-write store, sharded maps, unchanged objects shared across refreshes), `lookup` does prefix and fuzzy search over objects and loaded columns, scoped, bounded and ranked, `load_tables` loads the columns of named tables on demand and cancellably, `table_state` tells "not loaded" from "no columns", and `foreign_keys` resolves the targets of loaded tables. ADR-0022, an updated "Schema catalog" page and a `catalog_index` benchmark on 5,000 tables (also run by `bench.yml`).
- `verify-full` TLS through an SSH tunnel on macOS and Linux: `sqler-core` `TlsConfig` gains `server_name`, the connect pipeline sets it to the connection's original host, and the `PostgreSQL` and `MySQL`/`MariaDB` drivers verify the certificate against it through a private local socket bridge. Windows still refuses it. ADR-0019.
- RSA without the `rsa` crate (RUSTSEC-2023-0071 stays out of the tree, no advisory ignore): RSA SSH user keys (OpenSSH, PKCS#1, PKCS#8; 2048/3072/4096 bits; `rsa-sha2-256`/`-512`) through a `ring` signer in `sqler-tunnel`, and the `MySQL` plaintext RSA password exchange (`caching_sha2_password` cold cache, `sha256_password`) through a vendored `sqlx-mysql` 0.9.0 patch pinned `=0.9.0` that encrypts with `aws-lc-rs`. Limits: no SHA-1 `ssh-rsa`, no RSA-only host keys, legacy-encrypted PEM refused; the plaintext exchange runs only with an explicit `ssl-mode=disabled` (never as a `prefer` fallback, so a stripped TLS offer cannot downgrade), and even then it is open to a man-in-the-middle: only `require`/`verify-ca`/`verify-full` protect the password. `deny.toml` bans the `rsa` crate; `check-spdx.sh` skips `vendor/`. New `ssh` container tests (`start-sshd.sh`, gate id `ssh`) and a MySQL cold-cache test in the CI `db` job. `TunnelError::UnsupportedKeyType` is removed, and the committed test RSA keys under `crates/sqler-tunnel/tests/fixtures/` are gone (tests generate keys with `ssh-keygen`). ADR-0018; ADR-0010 and ADR-0013 point to it.
- SQL text services in `sqler-sql`, all pure and built on one hand-written, dialect-aware lexer that never fails: `split` and `statement_at` (exact byte ranges; strings, comments, dollar quotes, `BEGIN ... END` bodies and `MySQL` `DELIMITER` handled), `placeholders` (`$1`, `?`, `?1`, `:name`, `@name`, `$name` per dialect), fail-safe `classify`/`classify_each` (`Read` only when no write syntax, executable comment or non-allowlisted function is found) and an idempotent, comment-preserving `format`. No new dependencies. ADR-0020 (own lexer instead of `sqlparser`; `AGENTS.md` §2 updated) and the architecture page "SQL text services".
- Query history and saved queries in `sqler-config` (no UI yet): `history.jsonl` (JSON Lines, one versioned entry per query with SQL, connection, start time, duration, outcome and row count; default cap 10,000 entries, atomic compaction, corrupt or newer-version lines reported and kept, always-on credential redaction, `enabled` switch and `clear`) with a thread-safe `HistoryStore` and text and connection search, and `queries.toml` (versioned, hand-editable saved queries with folders, tags and an optional connection binding). New direct dependency `serde_json`. ADR-0021 and the Settings page sections for both files.
- Object browser in the desktop app: a lazy tree under each open connection (schemas, object folders, columns) with a loading state, a virtualized sidebar list, a context menu per node kind (open data, generate CREATE, SELECT, INSERT and DROP into read-only DDL tabs, copy name, refresh with progress and cancel, properties), DROP only after a dialog that shows the exact SQL and a second confirmation on `prod` connections, 19 `object:*` commands and arrow keys and Enter in the focused sidebar. Shift+F10 and Menu open the command palette filtered to `Object:` (no programmatic context menu in `gpui-component` 0.8.0). New public module `sqler_ui::browser`, ADR-0017, the user guide page "Object browser" and a `browser_tree` benchmark (also run by `bench.yml`).
- DDL and script generation for `PostgreSQL`, `MySQL`/`MariaDB` and `SQLite` (`sqler-sql`). ADR-0015 and the user guide page "DDL and scripts".
- Connection manager in the desktop app: a form for new and edited connections (driver, target, colour, environment, group, TLS, SSH tunnel), passwords stored in the keychain, a cancellable "Test connection", nested groups with create, rename, delete and drag or command based move, a confirmed delete that also removes the keychain entries, and `prod` connections that stand out. One connect pipeline (secret, SSH tunnel, TLS, driver) in `sqler-app` behind the `Connector` trait of `sqler-ui`; a host-key trust dialog; open sessions and tunnels are closed on quit. `verify-full` TLS through an SSH tunnel is refused for now. ADR-0016 and the user guide section "In the app".
