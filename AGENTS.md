# AGENTS.md

The SQLer project handbook (v1). This file is the single source of truth for contributors and agents.
`CLAUDE.md` only points here. Per-crate `AGENTS.md` files are allowed; they must link back to this one.

## 1. Purpose

SQLer is a lightweight, native, open-source (Apache-2.0) SQL IDE written in Rust. It is not a
general code editor with a database plugin: the database is the centre of the UI. Connections and
schema objects are first-class, and SQL editing is one activity among several.

It takes the best of three tools and leaves their weaknesses behind:

| Steal from | What | Avoid |
| ---------- | ---- | ----- |
| **Beekeeper Studio** | Clean, fast, uncluttered UX; tabs; quick connection switching; inline cell editing; schema-aware SQL autocompletion; "AI Shell" that learns the schema and can run queries to verify its own answers | Electron weight; JS runtime; closed Pro features |
| **Azure Data Studio** | Notebook-style results, excellent results grid (sort/filter/export/copy-as), connection groups, extension ecosystem, keyboard-first workflow, dashboards per connection | Being a fork of a general-purpose editor; retired by Microsoft in 2026 |
| **pgAdmin** | Deep object browser (schemas, tables, views, functions, triggers, roles, extensions), DDL generation for every object, EXPLAIN visualiser, query history, server-side object properties | Slow web UI; cluttered dialogs; Python/Flask stack |

Non-negotiables: Rust everywhere (edition 2024, stable toolchain pinned in `rust-toolchain.toml`);
lightweight (cold start < 500 ms, idle RSS < 150 MB with three connections, release binary < 80 MB, ADR-0069);
fully open source (Apache-2.0, SPDX header in every source file); modular; newest libraries,
verified on crates.io; documentation is part of the deliverable; cross-platform (Linux, macOS,
Windows); no AI feature executes a write statement without explicit user confirmation.

## 2. Architecture

Cargo workspace. Layered; dependencies flow downward only. Members are `crates/*` and `xtask`.

| Crate | Layer | Responsibility |
| ----- | ----- | -------------- |
| `sqler-core` | L0 | Domain types: Connection, Catalog, Query, ResultSet, Value, DataType; no I/O |
| `sqler-driver-api` | L1 | `Driver` trait, streaming result protocol, cancellation, introspection trait |
| `sqler-ai-api` | L1 | `AiProvider` trait, message and tool types, streaming, token accounting |
| `sqler-sql` | L1 | SQL text services on an own lexer (statement splitting, cursor lookup, placeholders, fail-safe classification, formatting), dialect handling, DDL generation; `sqlparser` only for later AST needs (ADR-0020) |
| `sqler-plugin-api` | L1 | WIT package, manifest and capability model; wasmtime-free (host bindings live in `sqler-plugin-host`) |
| `sqler-config` | L1 | Settings, keybindings, connection store, keychain |
| `sqler-tunnel` | L1 | SSH session and local port forward (russh); drivers connect to a local address |
| `sqler-update` | L1 | Check-only update client: fetches one Ed25519-signed manifest from the GitHub Releases `latest/download` asset (`ring`, `reqwest`), reports a newer version, never downloads a binary; linked into `sqler-app` by the default-on feature `update` (R4, ADR-0066 note); trusted key since R17 |
| `sqler-driver-postgres` | L2 | `PostgreSQL` driver (sqlx / tokio-postgres) |
| `sqler-driver-mysql` | L2 | `MySQL` and `MariaDB` driver (sqlx) |
| `sqler-driver-sqlite` | L2 | `SQLite` driver |
| `sqler-driver-mssql` | L2 | SQL Server native engine (`tiberius`, `rustls` with `ring`) behind the plugin `plugins/sqlserver`; linked only with the feature `driver-mssql`, off by default (ADR-0071, ADR-0063) |
| `sqler-driver-duckdb` | L2 | `DuckDB` native engine (bundled C++) behind the plugin `plugins/duckdb`; linked only with the feature `driver-duckdb`, off by default and out of 1.0 (ADR-0070, ADR-0063) |
| `sqler-ai-ollama` | L2 | Ollama provider |
| `sqler-ai-anthropic` | L2 | Anthropic provider |
| `sqler-ai-openai` | L2 | OpenAI and any OpenAI-compatible endpoint |
| `sqler-ai-mistral` | L2 | Mistral provider |
| `sqler-catalog` | L2 | Schema cache, incremental refresh, search index, dependency graph |
| `sqler-completion` | L2 | Intellisense engine: scope analysis, alias resolution, ranking; pure functions, heavily tested |
| `sqler-export` | L2 | CSV, JSON, SQL `INSERT`, Markdown, Parquet and XLSX writers behind a push-style `RowWriter` API and a format registry (ADR-0028); Parquet and XLSX sit behind the cargo features `parquet` and `xlsx` (ADR-0029) |
| `sqler-import` | L2 | Connection import from other tools (pgAdmin `servers.json` first; ADR-0067): per-tool `Source` parses a bounded buffer, `plan` is the dry run against the store, `apply` adds only new connections and writes only secrets the user typed; no foreign secret value is ever imported; no driver crate, no `sqler-ui`; the import wizard (R9, ADR-0067 amendment 2) lives in `sqler-ui` (`connections/import`, `workspace/import.rs`), which depends on `sqler-import` directly |
| `sqler-ai-tools` | L3 | Tool set exposed to models: catalog tools, `run_query`, `sample_rows`, `explain_query` (guarded by classification, approval and limits), `search_data`; host traits `SessionSource`, `Approver`, `UiHost` (ADR-0036) |
| `sqler-plugin-host` | L3 | Plugin loading, sandboxing, capability grants, lifecycle (ADR-0057): engine-free core by default, wasmtime runtime behind `cl` / `pulley-rt`, `NetEgress` behind `net`; off in `sqler-app`; data access through `DataService`/`QueryApprover` (ADR-0058) |
| `sqler-mcp` | L4 | MCP server (in-crate JSON-RPC layer; `rmcp` was measured and not adopted, ADR-0040) exposing `sqler-ai-tools` to external agents |
| `sqler-acp` | L5 | ACP client: spawn and host Claude Code, Codex CLI, Gemini CLI and others inside SQLer |
| `sqler-ui` | L6 | GPUI app: workspace, tabs, panels, grid, editor, palette, themes |
| `sqler-cli` | L6 | Headless CLI (run query, export, start MCP server); proves the core is UI-independent |
| `sqler-app` | L7 | Desktop binary `sqler`: tokio runtime, driver registry, opens the `sqler-ui` window (ADR-0007) |
| `xtask` | tooling | Repository automation (generate WIT bindings, release, bench, plugin build) |

Layering: a crate may depend only on crates in lower layers.

```
L0 core
L1 driver-api, ai-api, sql, plugin-api, config, tunnel, update
L2 driver-*, ai-ollama/anthropic/openai/mistral, catalog, completion, export
L3 ai-tools, plugin-host
L4 mcp
L5 acp
L6 ui, cli
L7 app
```

Rules:

- Only `sqler-app` depends on `sqler-ui`; driver crates are wired only by binaries (`sqler-app`, `sqler-cli`). Check:
  `cargo tree --workspace -i sqler-ui` must show `sqler-ui` and `sqler-app` only (CI "Dependency rules" step).
- `sqler-core` and `sqler-completion` have no async, no I/O, no UI: pure and exhaustively unit-tested.
- Drivers communicate through `sqler-driver-api` only. The UI never imports a driver crate.
- Every long-running operation is cancellable and reports progress through a channel; the UI thread never blocks.
- The public API of every crate is documented (`missing_docs` is a workspace lint).
- Drivers, AI providers and plugins are behind traits and can be compiled out with feature flags.
- Plugin guests and first-party plugin shells live in the separate workspace `plugins/` (not a member of the root workspace): `template`, `hello-panel`, `exporter-markdown`, `fixtures/*` (guests for `wasm32-wasip2`), and the manifest-only host-driver shells `sqlserver` and `duckdb`. Plugins reach SQLer only through `sqler-plugin-api` (WIT) and `sqler-plugin-host` (ADR-0055, ADR-0057).

- Plugins (P3, ADR-0054): guest crates live in the separate workspace `plugins/` (own `Cargo.lock`, excluded from the root workspace). `plugins build` compiles them for `wasm32-wasip2` into `target/plugins/cargo` and stages each plugin as `target/plugins/<debug|release>/<id>/{sqler.toml,<component>}`; `plugins check` runs fmt and clippy on the guests; `plugins clean` removes `target/plugins`. Exit codes: 0 ok, 1 failure, 2 usage error. The CI `plugins` job builds (debug and release) on Linux/macOS/Windows; on Linux it also runs `plugins check`, `cargo deny` over `plugins/Cargo.toml` and `plugins clean`. See `plugins/README.md`. The `probe` fixture (`plugins/fixtures/probe`) misbehaves on command; `crates/sqler-plugin-host/tests/guests.rs` runs it end to end when `SQLER_PLUGIN_FIXTURES=target/plugins/debug` is set (`SQLER_TEST_REQUIRE_PLUGINS=1` makes a missing fixture a failure; the CI `plugins` job sets both), and the `check` job runs the host tests with `--features cl,net`. The `deny` job asserts that `sqler-app` has no `wasmtime` in its default tree (ADR-0057).
- Release (ADR-0064): `.github/workflows/release.yml` builds the release artifacts with cargo-dist (`dist-workspace.toml`). A PR touching the release files builds Linux x86_64 only unless it has the label `full-ci`; `workflow_dispatch` is always a dry run and works only once the file is on `main`; publishing happens only on a `v*` tag. The file is hand-maintained (`allow-dirty = ["ci", "msi"]`): after a cargo-dist upgrade re-run `dist generate` into a scratch directory and diff.
- Licence bundle (R14, ADR-0064 amendment 2): `THIRD-PARTY-LICENSES.txt` is generated, never committed (git-ignored). The `plan` job runs `third-party-licenses.sh` once before `dist plan`; `build` and `global` download it; cargo-dist `include` puts it, with `NOTICE` and `licenses/`, into every archive, and `crates/sqler-app/wix/main.wxs` (hand-edited, `allow-dirty` has `msi`) into the MSI. The SBOM is one `sqler-app_<triple>.cdx.xml` per target. Audit and duties: `docs/src/licenses.md`.
- Benchmarks (R12): `cargo run -p xtask -- bench` measures one binary, either `--bin PATH` (a release artifact) or a local `cargo build --release -p sqler-app --locked --features <the dist-workspace.toml line>` (it refuses `driver-duckdb`). It prints `key=value` lines and writes `<out>/bench-<date>-<commit7>-<os>.json` (default `target/bench-results`): `binary_bytes` against 83,886,080, cold start (hyperfine over `--exit-after-first-frame`) and idle RSS (`--open-sessions`, three `SQLite` sessions) each with variant `none` (no plugin) and `plugin` (SQL Server manifest plus an approved grant) in throwaway config directories, and the five benches (`grid_viewport`, `grid_sort`, `editor_buffer`, `editor_intellisense`, `completion`). It needs `hyperfine` and a display. Exit codes: 0 within budget, 1 a breach or a failed measurement (the report is still written), 2 usage error. `.github/workflows/benchmarks.yml` (`workflow_dispatch`, and after a successful Release dry run) runs it on Linux, macOS and Windows against the Release artifacts and uploads the results; it never builds `sqler-app`. Method and the published table: `docs/src/benchmarks.md`.
- CI behaviour (ADR-0068): a `changes` job (`dorny/paths-filter`) decides which areas a pull request touches (`rust`, `ui`, `plugins`), and the other jobs skip their work when nothing relevant changed. Every check name still reports on every PR (a skipped matrix job would report the unexpanded name, so matrix jobs run and skip their steps; non-matrix jobs use a job-level `if`), and the extra check `CI result` fails when any CI job failed or was cancelled (a skipped job passes). On `main` and on `workflow_dispatch` everything runs, on all three OSes. On a PR, Windows `check` builds and tests only the crates with a Windows-only history (`-p sqler-plugin-host sqler-plugin-api sqler-config xtask sqler-acp sqler-mcp sqler-cli sqler-tunnel sqler-import` and the `agent_flow` and `guard_suite` tests of `sqler-ui`); Windows clippy is its own job `clippy (windows-latest)`. On a PR, macOS `check` runs clippy and nextest for the whole workspace except the platform-agnostic crates listed in the `MAC_SKIP` env of `ci.yml` (sql, catalog, completion, drivers, export, AI clients; the macOS-specific code is in `sqler-config` and `sqler-ui`, and Linux runs the rest). Linux always runs everything. A crate with new OS-specific code must stay out of `MAC_SKIP` and join the Windows list. Force a full PR run with the label `full-ci` (read at the next push) or with `gh workflow run ci.yml --ref <branch>` (a dispatch is full; `-f full=false` runs the PR subsets for a timing check). Caches are saved on `main` only; PRs restore them, so the first PR after a cache eviction is slow. A newer push cancels a running PR run, never a run on `main`. `bench.yml` runs on `main` and on PRs touching what the benches build, `size.yml` runs Linux only on PRs (all OSes on `main`, dispatch and `full-ci`), `spike.yml` and `plugin-spike.yml` run on `main` and on PRs touching `spikes/**`. Timings: `sh .github/scripts/ci-timings.sh <workflow-file> <limit> [branch|event]` (read-only `gh` collector).
- CI (`.github/workflows/ci.yml`) runs this subset of the commands above: fmt, clippy, nextest on Linux/macOS/Windows; plugins build on Linux/macOS/Windows; deny, docs (`cargo doc` and `mdbook build docs`), spdx on Linux. Since T5 the Linux `check` and `docs` jobs install the GPUI build packages with apt, and the macOS `check` job guards the Metal toolchain; the `deny` job also runs the "Dependency rules" step.
- DB tests (ADR-0009): `crates/sqler-driver-postgres/tests/docker/start-postgres.sh <outdir>` starts `PostgreSQL` with TLS in Docker (container `sqler-test-postgres`, `127.0.0.1:54329`) and prints `KEY=value` lines; locally use `eval "$(sh crates/sqler-driver-postgres/tests/docker/start-postgres.sh /tmp/pg | sed 's/^/export /')"`. The tests read `SQLER_TEST_POSTGRES_URL` and `SQLER_TEST_POSTGRES_CA` (the pattern is `SQLER_TEST_<DB>_URL`/`_CA`); when the URL is unset they print `skipped: <VAR> is not set (see AGENTS.md §3)` and pass. `SQLER_TEST_REQUIRE_DB=postgres` (a comma list of ids) turns a missing variable into a panic. Test files are `tests/db_<db>*.rs`, so the filter above selects them. Remove the local container with `docker rm -f sqler-test-postgres`. `MySQL` and `MariaDB` (ADR-0010): `sh crates/sqler-driver-mysql/tests/docker/start-mysql.sh <outdir> [mysql|mariadb]` (container `sqler-test-mysql`, `127.0.0.1:33069`, images `mysql:8.4` and `mariadb:11.8`) prints `SQLER_TEST_MYSQL_URL` and `SQLER_TEST_MYSQL_CA`; run the tests once per variant; remove with `docker rm -f sqler-test-mysql`. SSH tunnel RSA tests (ADR-0018, gate id `ssh`): `sh crates/sqler-tunnel/tests/docker/start-sshd.sh <outdir>` (container `sqler-test-sshd`, Alpine OpenSSH; sshd on `127.0.0.1:33256` limited to `rsa-sha2-256` and `33512` to `rsa-sha2-512`) generates RSA test keys with `ssh-keygen` and prints `SQLER_TEST_SSH_HOST`, `SQLER_TEST_SSH_PORT_SHA256`, `SQLER_TEST_SSH_PORT_SHA512`, `SQLER_TEST_SSH_USER`, `SQLER_TEST_SSH_KNOWN_HOSTS`, `SQLER_TEST_SSH_KEY_RSA`, `SQLER_TEST_SSH_KEY_RSA_PEM`, `SQLER_TEST_SSH_KEY_RSA_PKCS8`, `SQLER_TEST_SSH_KEY_RSA_ENC` and `SQLER_TEST_SSH_KEY_PASSPHRASE`; `tests/ssh_rsa.rs` skips without them; remove with `docker rm -f sqler-test-sshd`. `SQL Server` (ADR-0071, gate id `mssql`): `sh crates/sqler-driver-mssql/tests/docker/start-mssql.sh <outdir>` (container `sqler-test-mssql`, `127.0.0.1:14333`, image `mcr.microsoft.com/mssql/server:2022-CU27-ubuntu-22.04`, about 1.5 GB, Developer edition EULA, TLS forced with an own CA) prints `SQLER_TEST_MSSQL_URL` and `SQLER_TEST_MSSQL_CA`; the tests are `crates/sqler-driver-mssql/tests/db_mssql*.rs` and skip without them; remove with `docker rm -f sqler-test-mssql` (and `docker rmi` the image when done). The feature `driver-mssql` of `sqler-app` and `sqler-cli` is off by default and links the engine behind the `sqlserver` plugin; `cargo tree -p sqler-app -e normal --prefix none | grep '^tiberius '` prints nothing by default.
- CI has a Linux `db` job (no GPUI apt packages) that starts the server with the script, sets `SQLER_TEST_REQUIRE_DB=postgres,mysql,ssh,mssql`, runs `cargo nextest run -p sqler-driver-postgres --no-tests=fail`, then the same for `sqler-driver-mysql` against `MySQL` 8.4 and `MariaDB` 11.8, a step that starts the SSH server and runs `cargo nextest run -p sqler-tunnel --no-tests=fail`, steps that start SQL Server 2022 with `start-mssql.sh`, run `cargo nextest run -p sqler-driver-mssql --no-tests=fail` and remove the container in an `if: always()` step, and CLI smoke tests with `--driver postgres` and, for each of `MySQL` and `MariaDB`, `--driver mysql`.
- SPDX check (`sh .github/scripts/check-spdx.sh`) prints the offending paths and exits 1 when a tracked `*.rs` file lacks the header on line 1; it prints nothing otherwise. It skips `vendor/` (third-party code that keeps its upstream licence files, ADR-0018).
- `vendor/` holds third-party source copied in for a `[patch.crates-io]` entry, today only `vendor/sqlx-mysql` (sqlx-mysql 0.9.0 plus an `aws-lc-rs` backend, ADR-0018). It is not a workspace member, so fmt and clippy skip it, and it gets no SPDX headers. Its README states the maintenance procedure; no other change belongs there.
- CI tools (pinned, see `docs/src/dependencies.md`): `cargo install --locked cargo-nextest@0.9.148 cargo-deny@0.20.2 mdbook@0.5.4`. `cargo-about@0.9.2` (licence bundle of `release.yml`) and `cargo-cyclonedx@0.5.9` come as prebuilt binaries through `taiki-e/install-action`.
- `.github/workflows/bench.yml` runs the grid viewport, grid sort, catalog tree, catalog index, browser tree and completion benchmarks on Linux for pull requests (base vs PR in one job).
- `.github/workflows/size.yml` reports the release `sqler` size on Linux/macOS/Windows (main, `workflow_dispatch`, PRs touching `crates/**`, `Cargo.toml`, `Cargo.lock`, `vendor/**`); report only, budget 80 MB (83,886,080 bytes, ADR-0069 amended).
- Update check (R4, ADR-0066 note): feature `update` of `sqler-app` is ON by default (`reqwest`, `ring` and `semver` are already linked); `--no-default-features` compiles the client out and the UI then shows "not part of this build". The `cargo tree ... | grep '^sqler-update '` command above prints a line by default. The setting `check_for_updates` in `settings.toml` is off by default, and while it is off no request is made, including from the manual command. State lives in `update-state.toml` (last attempt, failure count, dismissed version only). Commands: `app:check-for-updates`, `app:open-release-notes`, `app:dismiss-update-notice`, `settings:toggle-update-checks`. `cargo test -p sqler-app update::` runs the mock-server tests (no real network).
- Plugins in the app (ADR-0060): feature `plugins` of `sqler-app` is OFF by default (ADR-0054 size rule: on only if every OS stays below 83,886,080 minus a 1 MiB reserve = 82,837,504 (ADR-0069 amended); the figures are in the ADR). `cargo tree -p sqler-app -e normal --prefix none | grep '^wasmtime '` prints nothing by default and a line with `--features plugins`; `cargo tree -p sqler-ui -i wasmtime` prints nothing. `--plugin-dir <PATH>` (repeatable, plugins builds only) is the only source of development plugin paths; `target/plugins` is never searched. Plugin choices are in `plugin-prefs.toml`, grants in `plugin-grants.toml`.
- `DuckDB` (ADR-0070, amendment 2): OUT of v1.0. The code stays, disabled; the feature is never part of a release artifact, installer or update manifest, and no document may promise it in 1.0. The engine `sqler-driver-duckdb` compiles the bundled C++ `DuckDB` (about 8 CPU-minutes uncached), so no PR job builds it: workspace jobs use `--workspace --exclude sqler-driver-duckdb` and the explicit feature list `WS_FEATURES` of `ci.yml` instead of `--all-features` (the `deny` job asserts the list is complete), and the separate `duckdb` job (manual `workflow_dispatch` only, never on PRs or main, Linux; run `gh workflow run ci.yml --ref <branch>` and dispatch it before touching the engine) builds and tests it. The feature `driver-duckdb` of `sqler-app` and `sqler-cli` implies `plugins`, is OFF by default and adds about 43 MiB to the release binary (over the 80 MB budget by design); `cargo tree -p sqler-app -e normal --prefix none | grep "^duckdb "` prints nothing by default. A `duckdb` bump must re-run `cargo tree -i webpki-roots` and `cargo deny check`.
- Plugin AI tools (ADR-0062): `sqler-ai-tools` owns the `ExternalTools` seam and never depends on `sqler-plugin-host`; the adapter is `sqler-app/src/plugins/ai.rs` (feature `plugins`). A plugin tool is listed only on a surface that has an `AiAudit` (so `ToolSet::with_external_tools` is called only from `ai/audit/sink.rs`), every plugin statement is approved through the surface's approver (`ExternalContext::approve`), and `sqler-cli mcp` lists no plugin tools. Guest tests of the `ai-probe` fixture need `wasm32-wasip2` and run in the CI plugins job (`SQLER_TEST_REQUIRE_PLUGINS=1`).
- `.github/workflows/pages.yml` publishes the book (`target/book/`) to GitHub Pages on push to `main`.
- Bench: `cargo bench -p sqler-ui --bench grid_viewport -- [--rows N --columns N --batch N --viewport N --samples N --save PATH --compare PATH --threshold-pct P --slack-ns S --budget-p95-ns B]`. Also `--reps N` and a repeatable `--compare`; `--pr FILE` (repeatable) judges saved runs. Rule: p95 more than 25 % + 100 ns (cells p95: 25 % + 500 ns) above the base branch, taken as the minimum over interleaved base and PR rounds, or p95 above 1 ms, fails `bench.yml`. Method and results: `docs/src/benchmarks.md`. The release CLI is still measured by hand as described there.
- Grid sort bench: `cargo bench -p sqler-ui --bench grid_sort -- [--rows N --columns N --samples N --window-samples N --reps N --save PATH --compare PATH --threshold-pct P --sort-slack-ns S --filter-slack-ns S --viewport-slack-ns S --budget-sort-ns B --budget-filter-ns B --budget-viewport-ns B --budget-slice-ns B --budget-sort-slow-ns B --budget-sort-url-ns B]`. ## 4. Coding standards

- `#![forbid(unsafe_code)]` in every crate except where FFI is unavoidable (drivers, wasmtime glue); document each exception.
- Workspace-level lints: `clippy::pedantic` as warn, selected lints as deny; `missing_docs` warn on public crates.
- No `unwrap`/`expect` outside tests and `main`; use typed errors.
- Async: never hold a lock across an `.await`; never block the UI executor; every spawned task has a cancellation path.
- UI: every user action is a `Command` with an ID; no business logic in views; views render state, actions mutate state.
- Tests: unit tests next to code; integration tests under `tests/`; DB tests (`tests/db_<db>*.rs`) start no containers themselves: a script per database starts one, the tests read `SQLER_TEST_<DB>_URL` and skip when it is unset (see §3).
- Performance: any PR touching the grid, catalog or completion must include a benchmark result in its description.
- Naming: crates `sqler-*`, features `driver-*`, `ai-*`; commands `category:action`, where action is one or more hyphenated lowercase segments (`app:quit`, `workspace:open-command-palette`).

Workspace lints (root `Cargo.toml`, inherited with `[lints] workspace = true`):

| Lint | Level |
| ---- | ----- |
| `unsafe_code` (rust) | forbid |
| `missing_docs` (rust) | warn |
| `clippy::pedantic` (priority -1) | warn |
| `clippy::unwrap_used`, `clippy::expect_used` | deny (allowed in tests via `clippy.toml`) |
| `clippy::dbg_macro`, `clippy::todo` | deny |

`unwrap`/`expect` are denied workspace-wide and relaxed only in tests (`clippy.toml`); `main` must use an explicit `#[allow(clippy::unwrap_used, clippy::expect_used)]` if it needs them.

## 5. Definition of Done

A task is done only when:

- code is merged to `main`;
- tests exist and pass on all targets;
- public items are documented;
- user-facing behaviour is documented in the book;
- a CHANGELOG entry is written;
- benchmarks are within thresholds;
- no new `unsafe` without a `// SAFETY:` comment and a reviewer sign-off;
- no new dependency without a recorded version and rationale.

## 6. Iteration workflow

1. **Plan**: read this file and the roadmap; pick the next milestone items; write them as GitHub issues or tasks with acceptance criteria.
2. **Decide**: a new dependency, crate, public API or cross-cutting change needs an ADR first.
3. **Build**: small PRs; tests alongside code; docs alongside tests.
4. **Verify**: `cargo fmt --check`, `cargo clippy $WS --all-targets --features "$WS_FEATURES" -- -D warnings`, `cargo nextest run $WS`, `cargo deny check`, warning-free `cargo doc`, plugin build, benchmarks not regressed. Run on all three OSes when the change touches platform code.
5. **Document**: user guide, architecture page, CHANGELOG, this file (commands, gotchas, roadmap status).
6. **Report** (template below).
7. **Reflect**: anything that cost time twice goes into the Gotchas section.

Git: Conventional Commits; small PRs; English only; no AI attribution in commits or PRs.

End-of-iteration report, posted as `docs/reports/iteration-NNN.md`:

```markdown
## Iteration NNN — <date>
### Delivered
- <item> (PR #, docs page)
### Decisions
- ADR-00xx <title> — <one-line summary>
### Metrics
- cold start / idle RSS / binary size / completion p95 / test count / coverage
### Risks & blockers
### Next iteration plan
### AGENTS.md changes
```

## 10. Gotchas

- `clippy::doc_markdown` (pedantic) flags product names such as `SQLite`, `DuckDB` and `PostgreSQL` in docs; put them in backticks.
- The `pedantic` group needs `priority = -1`, or `clippy::lint_groups_priority` fires.
- A crate with `[lints] workspace = true` cannot override single lints. An FFI exception to `unsafe_code` needs its own `[lints]` table, documented.
- `cargo nextest` fails when there are no tests unless you pass `--no-tests=pass`.
- The crates.io API rejects requests without a User-Agent header.
- Never pin a version from memory; check crates.io. Check `max_stable_version`, not `max_version` (it can be a pre-release).
- The `cargo-dist` tool was renamed `dist`, but the `dist` crate on crates.io is unrelated; the crate is still `cargo-dist`.
- `clippy::unwrap_used`/`clippy::expect_used` are denied everywhere except tests; there is no exemption for `main`, so add an `allow` attribute there if needed.
- GitHub Pages must be enabled once by hand (Settings > Pages > Source: GitHub Actions) before `pages.yml` can deploy.
- Plugin guests are a separate workspace (`plugins/`), built only through `cargo run -p xtask -- plugins build` into `target/plugins/`. `cargo fmt/clippy --workspace` at the root skips them (use `plugins check`), and the `wasm32-wasip2` target comes from `rust-toolchain.toml`.
- `cargo bench` passes `--bench` to `harness = false` binaries; their argument parser must ignore it.
- CI installs the toolchain with a bare `rustup toolchain install`, which reads `rust-toolchain.toml` (rustup 1.28 or newer), so the Rust version is pinned in one place only.
- UI framework spike (ADR-0001): GPUI is accepted. The resolved GPUI crate is `gpui-pre` (=0.3.9, pulled by `gpui-component` 0.8.0), not `gpui` or `gpui-ce`; the check is `cargo tree -i gpui-pre`, since `cargo tree -i gpui` can never match. Application creation needs `gpui-pre-platform` (features `font-kit`, `x11`, `wayland`); `gpui-component` does not re-export it.
- Plugin runtime spike (ADR-0054): `spikes/plugin-runtime/` is its own workspace (host crate with one wasmtime variant per cargo feature, guests in their own workspaces for `wasm32-wasip2`). CI is `.github/workflows/plugin-spike.yml` (by push, `workflow_dispatch` works once the file is on `main`); local reproduction is in the spike README (`scripts/measure.sh <variant> <guests-dir> <outdir>`, throwaway rustup under `.tools/` when the machine has no `wasm32-wasip2`). `spike.yml` fires only on `spikes/ui-framework/**` and its own file (and `plugin-spike.yml` on `spikes/plugin-runtime/**`); since ADR-0068 both run on `push` to `main` and on pull requests, not on every branch push.
- CI gotchas (ADR-0068): a job-level `if` on a matrix job makes it report the unexpanded name `check (${{ matrix.os }})`, so a required `check (ubuntu-latest)` would wait forever; gate steps instead. The `full-ci` label is read when the run starts, so push again after labelling. Caches are written by `main` runs only (a PR run never saves), so after a `Cargo.lock` or toolchain change the first run on `main` is cold. A run listed at 70 minutes in the Actions UI (Size, run 39824753263) was a bookkeeping artifact of a cancelled run (its jobs ended after 5 minutes), not a slow build. Adding a new job to `ci.yml`: add it to `needs:` of `ci-result` and gate it on a `changes` output.
- Spike Linux apt packages: `libfontconfig-dev libwayland-dev libxkbcommon-dev libxkbcommon-x11-dev libx11-xcb-dev libxcb1-dev libvulkan1 mesa-vulkan-drivers vulkan-tools fonts-dejavu-core xvfb xauth cage pkg-config`. Software Vulkan is lavapipe (`mesa-vulkan-drivers`); the renderer shows as `llvmpipe` and GPUI runs on it with no extra setup.
- Headless Wayland in CI needs a `wl_seat`: `weston --backend=headless` has none and GPUI panics (`Wayland compositor does not provide wl_seat`). Use `cage` with `WLR_BACKENDS=headless WLR_RENDERER=pixman WLR_LIBINPUT_NO_DEVICES=1 WLR_HEADLESS_OUTPUTS=1`, unset `DISPLAY`, and check that the report says `display=wayland`.
- macOS: the GPUI build needs the Metal toolchain (`xcodebuild -downloadComponent MetalToolchain`, about 840 MB; the `macos-latest` image already has it). Windows CI renders with WARP (software D3D). On shared CI VMs first-frame times vary up to about 3.6x between runs; cold start is stable.
- macOS: a GPUI window may not present frames while the display is idle or the window is hidden, so smoke runs can stall (two manual runs ran 84 s and 120 s). Keep a watchdog and treat a one-off watchdog failure as environment, not as a GPUI failure.
- `hyperfine` 2.0 JSON has the mean at `results[0].summary.time_wall_clock.mean`. On Windows run it with `-N` and a quoted path, or it fails.
- Open follow-up from the first UI PR (T5): the 2-minute interactive macOS check has not been done. It covers the spike items (trackpad scroll, typing SQL, resizing the split) and the workspace shell (click and double-click a connection, two tabs on one connection, switch, close, the prod look). An agent cannot do it; the maintainer does it and records the result.
- The apt packages in `ci.yml` are the build-only set (`pkg-config libfontconfig-dev libwayland-dev libxkbcommon-dev libxkbcommon-x11-dev libx11-xcb-dev libxcb1-dev`); no runtime libraries are installed because no test opens a window.
- `cargo test -p sqler-ui` is GPUI-free (the views need the `gui` feature, which only `sqler-app` enables). `cargo clippy --workspace --all-features` and `--workspace` builds do compile GPUI.
- Never call `tokio::spawn` on the GPUI thread: there is no runtime context. Use `SessionBridge` (`Handle::spawn` plus a `oneshot` awaited with `cx.spawn`), see ADR-0007.
- `sqler --exit-after-first-frame` exits with code 0 after the first frame (cold-start measurement). On quit, open sessions are closed (ADR-0016): `app:quit` closes them under a 2 s bound; the window-close hook only gets about 150 ms. `sqler --open-sessions` opens every saved connection through the same pipeline after startup and idles (idle RSS with sessions open); it skips, with a stderr line holding the connection name and a fixed reason (never error text; only the host-key reasons add the jump `host:port`), any connection with a keychain secret, an untrusted SSH host key or a failed connect, so SQLer itself never prompts (an SSH agent may).
- Measuring the desktop app on macOS: the config directory is `$HOME/Library/Application Support/SQLer`, so run `sqler` with `HOME` pointed at a scratch directory to get a known `connections.toml` and leave the real config alone. `hyperfine` is at `/opt/homebrew/bin`, `mdbook` and `cargo-nextest` are in `~/.cargo/bin` and may be off `PATH`.
- Secrets (T5, ADR-0012): headless Linux CI has no Secret Service, so tests use `MemoryStore`; `KeychainStore` is only checked by hand with `cargo test -p sqler-config -- --ignored keychain_round_trip` on a desktop session. `keyring` 4.x has no native-backend features of its own: enable `v1`, which turns on the Keychain, Credential Manager and `zbus` Secret Service (`crypto-rust`, `async-io`) stores per target. Never use keyutils, `vendored` `libdbus`, OpenSSL crypto, a `tokio` runtime feature or a mock store. `SecretStore` calls block; async callers use `spawn_blocking`.
- `PostgreSQL` test server (ADR-0009): the server rejects a TLS key it does not own or that is group/world readable, so the script copies the key inside the container, runs `chown postgres` and `chmod 600`, then starts the server. GitHub `services:` cannot pass server arguments (`-c ssl=on`), hence the `docker run` script. The image's init server listens on the socket only; wait with `pg_isready -h 127.0.0.1`, not the socket.
- `PgConnectOptions` has a `Debug` that prints the password: never derive `Debug` on a struct that holds it and never log it (`PgCanceller` has a hand-written `Debug`). Driver errors must not echo the target.
- `MySQL` test server (ADR-0010, ADR-0018): `sqlx-mysql` is the vendored `vendor/sqlx-mysql` (pinned `=0.9.0`, `aws-lc-rs` RSA backend), so a plaintext login to an account not cached by `caching_sha2_password` works only with an explicit `ssl-mode=disabled` (the patched `encrypt_rsa` refuses otherwise, so a stripped TLS offer under `prefer` cannot downgrade), and even then the in-band server key lets a man-in-the-middle read the password: only `require`, `verify-ca` and `verify-full` protect it. The test `rsa_exchange_over_plaintext_cold_cache` covers both (MySQL only; `MariaDB` has no such plugin; it uses a TLS-stripping proxy). On every `sqlx` bump re-sync the vendored copy (see its README). `aws-lc-sys` on x86_64 Windows uses the `prebuilt-nasm` feature (target-specific dependency in `sqler-driver-mysql`); if Windows CI breaks on it, part (b) reverts to NO-GO (ADR-0018). `deny.toml` bans the `rsa` crate; never add it. Text in a `_bin` collation and `MariaDB` `JSON` arrive as `Bytes`; `sqlx` reports a zero date as NULL, so the driver reads date columns as raw bytes. `KILL QUERY` needs a side connection; a killed `SLEEP()` returns 1, not an error.
- A DB test that skips is green: without `SQLER_TEST_REQUIRE_DB` a missing variable only prints a skip line. CI sets it so the `db` job cannot pass without running. An unreachable server always fails.
- `sqler-tunnel` (ADR-0013): `russh` is built with `ring` only and never with its `rsa` feature. RSA user keys work through `rsa_key.rs` (ADR-0018): OpenSSH, PKCS#1 and PKCS#8 files, 2048/3072/4096 bits, `rsa-sha2-256`/`-512` only; no SHA-1 `ssh-rsa`, no RSA-only host keys, legacy-encrypted PEM refused (errors name Ed25519/ECDSA). RSA keys in an agent need no special code. RSA tests need the `start-sshd.sh` container (gate id `ssh`); the test keys are generated, never committed. Host keys are never accepted silently: use `trust_host_key` after the user confirms the fingerprint. Tests use an in-process `russh` server, no Docker.
- Connect pipeline (ADR-0016): `verify-full` TLS through an SSH tunnel is refused (`TlsHostnameThroughTunnel`; an explicit TLS mode overrides the URL `sslmode`/`ssl-mode`, and a URL verify-full counts only without an explicit mode) because the driver would verify `127.0.0.1`; lifting it needs a server-name field on core `TlsConfig` plus driver support. A `Tunnel` must not be dropped outside a tokio runtime: `TunnelledSession` closes it on the runtime handle. A stored target never has user info; the database user is `?user=` and the password is injected at connect time (a password with a target that has no user is refused). `sqler-ui` talks to the pipeline only through the `Connector` trait.
- Object browser (ADR-0017): `ObjectTree` never calls the catalog; `expand` and `*_loaded` return `CacheKey`s and the workspace turns them into `Effect::LoadCatalog`. Tokio work still goes only through `SessionBridge`. DROP SQL comes only from `DropFlow::confirm` (once, twice on `prod`); nothing else may build a `RunJob(Drop)`. `gpui-component` 0.8.0 `ContextMenuExt` cannot open a menu from code, so `object:show-menu` (Shift+F10, Menu) opens the palette filtered to `Object: `. The sidebar is a `gpui::list` with a `ListState` that is diffed in `settle`; do not rebuild rows per frame. `Up`/`Down` walk groups, connections and tree rows through `Workspace::move_selection`.
- Query execution (ADR-0024): while a query runs, the tab's session is on loan to the `QueryJob` (`take_session`, returned in `query_finished`; closed there if the tab is gone), so a second run is refused. Cancel needs the session's `CancelHandle` and the job's `RunStop` (`stop.cancel()` sets the flag and cancels every `GridSink` through its `GridCancel`, which also wakes a paused statement); `SQLite` resets its own flag when `execute` starts, so without the flags a cancel between statements is lost. Parameters are bound through `Query::params` (`$k`, `?k`, `?` per occurrence), never spliced. `sqler-ui::query` is GPUI-free; the prod confirmation lists every non-`Read` statement once per run.
- Editor intellisense (ADR-0026): `sqler_ui::editor::intellisense` is GPUI-free; only `editor/view/provider.rs` uses `gpui-component`'s `CompletionProvider`. The direct `lsp-types` dependency must stay on the same line (0.97) as the one `gpui-component` uses (`cargo tree -i lsp-types` must show one version), or the provider traits see a different type. Catalog futures are awaited on the GPUI executor, never with `tokio::spawn`. `completion_menu_state` is `#[doc(hidden)]`; re-check it on a `gpui-component` bump. `editor:trigger-completion` is Ctrl+Space, which macOS may take for input source switching.
- Append-only files (`CHANGELOG.md`, `docs/src/SUMMARY.md`, `docs/src/adr/index.md`) conflict on every rebase of a stacked PR. After resolving one, check that no bullet or table row lost its newline (a `".- ` join happened on CHANGELOG line 24 and a blank line split a table in `benchmarks.md`), and that every table still has one cell count.
- A new gated bench follows the interleaved A/B plus judge pattern of the `grid_viewport` and `browser_tree` steps in `bench.yml` (T15), not a bare 25 % + ns rule or two sequential runs: base and PR rounds alternate in one step, each round saves a file, a judge-only call (`--pr`/`--compare`, repeatable) takes the minimum per side over the rounds, and the slack is absolute and sized to the metric (100 ns for the grid, 250 us plus a 1 ms floor for the browser tree). Shared runners only add time and drift by 2x between minutes. Gate a few-sample millisecond metric on its p50 and keep the p95 informational (a `WARN:`) apart from its absolute budget. Rationale, data and demos: `docs/src/benchmarks.md`. Linux CI figures are 1.5 to 3 times the macOS ones (PR #35: `diagnose_p95_ns` 5.04 ms against 2.4 ms here).
- The headless `editor_buffer` and `editor_intellisense` benches stop at the GPUI providers (`Rope::to_string`, LSP position mapping, debounce, paint), and are not in `bench.yml`. A typing or scrolling regression shows only on a display, so check it by hand on the 10,000-line script after editor changes.
- `[profile.release]` sets `strip = "symbols"` and `codegen-units = 1` (T14, binary size). A release build has no symbol names, so a panic backtrace shows addresses only, and a profiler shows none. For debugging build with `CARGO_PROFILE_RELEASE_STRIP=none cargo build --release -p sqler-app` (and `CARGO_PROFILE_RELEASE_DEBUG=line-tables-only` for line numbers). `cargo bench` inherits `release`, so it is stripped too. LTO and `panic = "abort"` were measured and rejected, see `docs/src/benchmarks.md`.
- Result grid credit gate (ADR-0027): only `GridCancel` (`GridSink::canceller`), `GridModel::cancel` or a dropped `GridModel` wake a paused ingest; setting the `CancelFlag` alone does not. Store `GridCancel`, never `cancel_flag()`, wherever a tab or run can be cancelled (`QueryJob::stop` is a `RunStop` for this reason; `Quit` cancels every grid). A paused statement holds the tab session, so later statements of a script stay `Pending` until fetch-all, cancel or close.
- Grid export (ADR-0032, `sqler_ui::export`): the writer (`write_feed`) always runs on tokio's blocking pool (`SessionBridge::blocking`) and blocks on a bounded feed (`FEED_CAPACITY` = 4 batches); never run it on the GPUI thread and never `tokio::spawn` for it. Loaded rows are copied out of the UI-owned `GridModel` on the UI thread by `LoadedCursor`, in slices with a time budget, so a million rows do not freeze a frame; keep the budget when touching it. A fresh run (`fresh_rows`) opens its own short-lived session and is allowed only for one statement that `classify_each` calls `Read` (`fresh_gate`, then `Workspace::fresh_check`); never re-run a write, a script or an unclassified statement. A paused statement holds the tab session (credit gate above), which is why the export does not borrow it. The target is written as `.<name>.<pid>-<job>.partial` and renamed on success (`PartialFile`); `ExportFailure` texts never carry the SQL, a path or a credential: `Connect` and `Driver` hold the user text of the connect pipeline or the driver, built only through `connect_text`/`driver_text` (add a fixed text there for any new error variant that can echo a target, path or secret). A dialog pins the tab's result generation (`Workspace::result_replaced`, called wherever a tab's table is replaced); if it changed, the export is refused.
- Sorted grid (ADR-0031): `GridControls::{apply, click_cell, click_header, is_selected, motion_moves}` take a `&dyn RowOrder` (pass `&tab.rows()`), and once a sort or filter is published a display row is not a model row; `Applied.scroll_row` is a display row. Map through the order before touching `GridModel` (copy, export of loaded rows, staged edits), or the wrong row is read.
- Inline editing (ADR-0033): the apply session and the transaction flag decide editability, and every doubt errs toward refusing (no edit rather than a wrong write). A keyless table is an explicit opt-in with a warning, and apply goes through the production gate once (see the Query execution entry). Only a display shows the cell editor key order, marks and dialogs; there is no headless GPUI to check them.
- `grid:toggle-cell-detail` has no default chord because Mod+Shift+I is the GPUI inspector on Linux and Windows; do not add one in `keymap.rs`. Mod+C and Mod+Shift+C are claimed only while a results table has focus, so the SQL editor's copy must keep working.
- Workbench (ADR-0042, ADR-0045): every tab close goes through `Workspace::request_close_tab` (prompts for pending edits, session loan, grid cancel); never remove a tab from `TabStrip` directly. `workbench.toml` is read leniently and a file from a newer SQLer is never overwritten (an invalid file is copied to `.bak` before the first save); a new field is additive, never a version bump. Query results show in the bottom panel, not in the tab body.
- Visual system (ADR-0043, ADR-0044): views take spacing, type sizes, radii and colours from `theme::tokens` and `workspace::chrome`, and icons from the Lucide set; the source guard `crates/sqler-ui/tests/view_tokens.rs` fails on hard-coded values in the restyled views. A new view must pass it. Shortcut labels come from `display_chord` (`⌘⇧P` on macOS, `Ctrl+Shift+P` elsewhere), never from a literal string. `LOCAL_KEYS` in `keymap/dispatcher.rs` is a hand-kept table of the hints for keys handled outside the keymap; change it together with the handler, nothing checks it.
- Screenshots (ADR-0047): `cargo test -p sqler-ui --features screenshots --test screenshots` renders 40 scenes in both themes (Metal on macOS, wgpu on Linux, skipped on Windows). A UI change updates `docs/src/screenshots/after/` by re-running the harness and committing the pictures; after a rebase re-run it, never hand-merge PNGs. A new view gets a scene in `workspace/view/scene.rs`. CI job `screenshots (linux)` uploads the artifact; `screenshots (macos)` is advisory.
- Measuring on the macOS desktop: the machine runs in two states, cold start about 115 or 135 ms and idle RSS about 73 or 102 MiB, on the same binary. Compare old and new builds interleaved in one session (build the base commit in a scratch worktree), not against a figure from another day, and delete the scratch worktree and its `target/` afterwards.
- Binary size: M4.5 spent about 3 to 4.5 times its +300 KiB budget (visual system and shell code and assets). `size.yml` is report only, so nothing stops a step from growing the binary; check the three lines on every UI PR. Linux is the tightest (54.1 MiB of 60).
- AI tool results (ADR-0037): tool results are enveloped, so parse them with `unwrap_untrusted`; never build `ToolResult` outside `ToolSet::finish`, which redacts, wraps and audits every call.
- Agent tab (ADR-0051): tests need the mock agent (`SQLER_TEST_MOCK_AGENT`, else `sqler-acp-mock-agent` next to the test binary; `cargo build -p sqler-acp --bins`). Stop an agent only through `AgentControl` (close/cancel), never by killing the pid; the teardown order lives in the runner. SQL approvals and ACP permissions share the ask-id contract; reach the queues through the `approvals`/`approvals_mut` seam in `workspace/ai_session.rs`.
- A yanked crate fails `cargo deny` (`yanked = deny`) the moment `cargo deny check` runs with a fresh index: `main` went red when `tokio 1.54.0` was yanked, fixed by updating to 1.54.1 (PR #78). Run `cargo deny fetch` before `cargo deny check` and never add an advisory ignore to get past it.
- `ship --timeout` takes seconds, not milliseconds; a value like 600000 waits for a week. Give every wait a timeout and keep one poller per PR; kill background commands you started before handing back.
- Source-scan tests (`view_tokens`, guard scans over `.rs` text) must tolerate Windows CRLF: split on `lines()` and never match a literal `\n`.
- `serde_json` `preserve_order` is enabled by some dependency, and feature unification turns it on for every crate in the build; code that relied on sorted object keys (audit lines, prompts, tool schemas) must not depend on the map order. Compare parsed values or sort explicitly.
- Parallel M5 PRs clashed on the append-only files (`CHANGELOG.md`, `AGENTS.md`, `docs/src/SUMMARY.md`, `docs/src/adr/index.md`, `docs/src/dependencies.md`) and, once, on a test (T19 and T15 both touched the `sqler-mcp` cancel test, red `main` until PR #78). After merging a stacked or parallel PR, re-run the whole workspace tests and rebase the second PR's append-only edits by hand.
- Timing tests must be deterministic: a 4 ms wall-clock budget in an export test flaked on shared runners. Inject a clock or count steps, and keep a wall-clock ceiling generous (the `parsing_is_fast` ceiling is 50 ms; the 1 ms budget is a measurement, not a gate).
- AI audit without a config directory: the AI surfaces get their audit sink only through `AiAudit` (`sqler-ui` `ai/audit/sink.rs`), which the `Workspace` owns and passes into the session, assist and agent starts. With no config directory the log is `None` and these surfaces are off with the reason `NO_AUDIT` (hub, query toolbar and notice); never build a sink anywhere else (a source-scan test enforces it). This replaces the earlier gap where they ran unaudited (H1, ADR-0037 addendum). A sink that exists but fails to write still fails open, counted and shown by the host.
- The `sqler-ui` library without the `gui` feature warns of dead code in `workspace/ai.rs` (`PendingSave`, `SaveQueue`); `cargo bench -p sqler-ui` prints it. The workspace clippy run enables the feature and stays clean.
- Plugin command namespaces (ADR-0060 addendum): a plugin command id is `plugin-<plugin>:<command>` (`object-plugin-`, `editor-plugin-`, `results-plugin-`, `panel-plugin-` for the others), built only by `plugins/contrib` and always passing `CommandId::new`; never register one by hand. After every manager load the workspace drops every plugin-namespaced command from the `CommandRegistry` (`retain`) and registers the current ones, then rebuilds `KeyDispatcher` and `Hints` from the saved override clone, so a key override for a plugin command works only after the plugin loaded (the dispatcher skips the startup "unknown command" notice for those categories). `recent_commands` drops plugin ids at startup for the same reason. Calls into a plugin go through the `PluginsBackend` futures with `SessionBridge::spawn`, never `tokio::spawn` on the GPUI thread.
- Host-engine plugins (ADR-0061, ADR-0063): a database engine cannot run as a `wasm32-wasip2` guest (ADR-0054), so SQL Server and `DuckDB` are manifest-only plugins over a native engine behind a default-off feature (`driver-mssql`, `driver-duckdb`, each implying `plugins`). The manifest `dialect` key has no consumer: `Dialect::from_driver_id` knows only the built-in drivers, so such a driver gets no statement splitting or classification and every statement asks for confirmation on a `prod` connection; fresh-run export, SQL `INSERT` export and the AI query tools refuse it. A new engine of this kind starts with its dialect in `sqler-sql`, not with the plugin shell. `rows_affected` must be `Some` for inline grid editing to apply.
- Plugin size rule (ADR-0060, ADR-0069): `plugins` is on by default only if every OS stays below 83,886,080 minus 1 MiB = 82,837,504 with it; Linux with it is 79,908,200 bytes at the M6 close, so the size alone no longer blocks it, but ADR-0069 does not flip `default`, `size.yml` prints both builds and nobody turns it on by editing `default`. Read the per-OS figures from the job logs (`gh run view --job <id> --log`, the line `sqler release binary on <OS>: default ... with --features plugins ...`).
- Building plugin guests needs `rustup` and the `wasm32-wasip2` target (`xtask plugins build` fails with a one-line error otherwise). A machine with no `rustup` cannot build them, run the guest tests (they skip green unless `SQLER_TEST_REQUIRE_PLUGINS=1`) or the `plugin_export` bench; do those in CI or install rustup.
- Metrics reports: take the numbers on merged `main` in a scratch `HOME`, label each as fresh, a CI run id or quoted, and never fill a gap with an estimate. Screenshot PNGs of the committed set can differ byte-wise from a fresh render on another day or machine state (on 2026-10-23, 54 of 70 differed while rendering correctly); do not commit a regenerated set unless a scene changed, and let the Linux CI artifact be the gate.
- Privacy and identity (public repository): no email, user name, home path or machine detail (CPU model, OS build, hostname; say "macOS arm64 (reference machine class)" or "Linux/Windows CI runners") in commits, PR text, reports or repo files (repo paths only); commits and merges use the public noreply identity through `GIT_AUTHOR_*` and `GIT_COMMITTER_*` environment variables, verified with `git log -1 --format='%ae|%ce'` before any push; a crates.io User-Agent is the generic `sqler-dev (https://github.com/alwatroos/sqler)`. A history rewrite needs the owner's decision.
